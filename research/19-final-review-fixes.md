# 19 · Final review: what to fix before the first install

Status: work brief, 2026-11-19. A pre-release review of the endpoint authentication (research/18) and of the fixes in research/17 found the proof and pinning construction correct, and ran 138 passing tests. Its verdict was to hold the first install until the items below are fixed. Each item gets a regression test that fails first. Two agents work from this document at the same time: **Part 1** (Linux host, updater, admission) and **Part 2** (apps, client, Mac, Windows, Android).

Neither agent asks questions while working: where this document leaves a choice, make it, and say what you chose and why in the final report.

## Part 1 · Linux host, updater, admission

Files: `apps/sunnad` (Linux), `crates/host`, `crates/capture`, `crates/input`, `crates/update`, `scripts/system-host.sh`, `scripts/sunna-host`, `scripts/linux-desktop.sh`, `scripts/release/install.sh.in`, `scripts/release/test-layout.sh`, `tools/login-test`, `docs/host-linux.md`.

1.1 **High. A failed migration leaves whole-machine sharing enabled.** System setup writes the new settings and unit and enables the unit before restarting it; if the restart fails, `set -e` exits before the readiness check and its cleanup, and the outer installer restarts the previous user host while the new system unit stays enabled for the next boot (`scripts/system-host.sh:57`, `:89`; `scripts/release/install.sh.in:58`). The reviewer's fixture: setup exit 19, system unit enabled, unit file present. Fix: start the candidate without enabling it; enable only after readiness; on any failure restore the prior unit, settings and enablement (or their absence).

1.2 **High. A seat change can be read as "nobody is here".** If logind selects session B between reading A's `ActiveSession` and A's properties, A reports `Active=false`; the code turns that into `None`, publishes an `empty` receipt, and setup can accept it and remove the old configuration before B has produced a frame (`apps/sunnad/src/linux_seat.rs:48`, `linux_machine.rs:237`, `scripts/system-host.sh:93`). Fix: distinguish an explicitly empty seat from an inconsistent observation (re-read until two consecutive observations agree), and make the receipt describe a consistent, still-current observation.

1.3 **High. The sign-in limits can keep the owner out.** A shared source address reaches the per-address penalty through stale keys, old apps talking to a proof-required host, or TLS alerts; the host-wide penalty then rejects even a new source with the right key and pin before it can present either, and the tests require that (`crates/host/src/admission.rs:34`, `:118`; `crates/host/src/lib.rs:507`). Fix: keep the deadline and the bounded pending capacity. Count only failed credential proofs as failures, not TLS or version mismatches. Replace the host-wide ban with bounded admission that always leaves room for new sources (for example a small reserved share of capacity and per-source backoff only), so that a correct viewer is admitted within a bounded time whatever others are doing. Add a test that holds every other limit at its maximum and shows a correct viewer still gets in.

1.4 **Medium. Recovery misses a dangling `current` whose last path component matches.** With a healthy `versions/1.0.0` and `current` pointing at `missing/1.0.0`, recovery compares only `1.0.0` and skips the repair (`crates/update/src/lib.rs:1102`; the layout test at `scripts/release/test-layout.sh:40` used a different name). Fix: compare the whole resolved target with the expected release directory and use the existing atomic flip when they differ. Add the same-name case to the layout test.

1.5 **Medium. The virtual-desktop launcher still checks displays the old way.** `scripts/linux-desktop.sh:125` uses plain `xdpyinfo` to decide a display is already running and to wait for it, which bypasses the verified connector and can use inherited authority. Fix: a small health check through the verified connector (a subcommand of `sunnad` is fine) for both uses; for per-user launches without session metadata, enforce or document the intended session binding (`crates/capture/src/x11.rs:40`).

1.6 **Medium. A quick A → B → A switch can be missed.** The observer and the fast checks compare current state, so two changes between observations leave the connection made for the first A in place (`linux_machine.rs:233`). Fix: a seat-change generation driven by logind notifications; any change of generation ends the stream. (The client side of the same finding is Part 2, 2.6.)

1.7 **Medium. A resolution change can leave keys held.** The worker's health thread calls `process::exit(1)` on an X11 resize, skipping the injector's cleanup while that X server lives on (`linux_worker.rs:176`, `crates/input/src/linux.rs:207`). Fix: signal the worker loop to unwind and release held input before exiting.

1.8 **Medium. `new-identity` starts a host that was stopped.** Both Linux paths replace the pair and run `restart` (`scripts/system-host.sh:119`, `scripts/sunna-host:687`). Fix: `try-restart`, and report a reload failure separately from a successful rotation.

1.9 **Low.** After a shareable login screen has been seen, `shares-greeter=1` stays when no greeter is selected or the login manager is removed (`linux_machine.rs:308`): clear it on the relevant lifecycle changes. A connection that negotiated the new protocol name (`sunna/8/auth1`) can still send a token-only first message to a host that allows older apps (`crates/host/src/lib.rs:560`): require the proof on that protocol name, and make the legacy test fixture negotiate the old name explicitly (`crates/host/tests/live_stream.rs:668`). `scripts/sunna-host:314` still tells LAN users there is no host identity check: say what is now true.

1.10 **Regression tests the review found too weak.** For research/17 item 1.1 the guest only reserves the abstract name without listening, so the old connector also passes: make the fixture listen, and assert it receives nothing. For 1.10 the logind-restart case also passed on the old code: add a deterministic same-id, changed-owner case. For 1.5 add the test described in 1.3 above.

## Part 2 · Apps, client, Mac, Windows, Android

Files: `apps/sunna/**`, `apps/android/**`, `crates/android`, `crates/client`, `crates/viewer`, `crates/transport` (tests only, plus what 2.9 needs), the macOS and Windows parts of `apps/sunnad`, `apps/sunna-cli`, `docs/security.md`, `docs/using.md`, `docs/troubleshooting.md`, `tools/identity-test`.

2.1 **Medium. A late probe answer attaches one computer's identity to another address.** In Add a Computer, start a probe for A, change the address to B, and let A answer during the debounce: the answer still matches the current sequence and writes A's pin into the form; B's probe then uses A's pin and Save can persist the pairing (`apps/sunna/ui/main.js:668`; the same ordering in `apps/android/.../MachineSheet.kt:261`). Reproduced by the reviewer against the real desktop handlers. Fix: invalidate the request the moment either field changes; tie a learned pin to the address and key it was learned for; keep a saved or imported pin separate from a draft probe result. Desktop and Android.

2.2 **Medium. A failed Save changes the pin anyway.** Re-adding a rotated computer writes its new pin before the record; if the record write fails or the process stops between the two, the record and its identity file disagree and the computer is refused both ways (`apps/sunna/src/machines.rs:186`, `apps/android/.../Machines.kt:256`, `crates/client/src/auth.rs:44`). Fix: one transaction, or a journal that is reconciled before any connection is admitted. Say in the docs what restoring a complete older backup does.

2.3 **Medium. "Allow this older computer" understates what it does.** The switch says the connection is unverified. It does more: while it is on, even a background probe sends the full key to whatever answers as an older host. The in-session warning lives in the optional stats bar, and a failed legacy probe can show "not fully verified" where the real state is a wrong key (`apps/sunna/ui/index.html:213`, `MachineSheet.kt:136`, `crates/client/src/reach.rs:171`, `crates/viewer/src/viewer.rs:303`). Fix: say it plainly beside the switch, in one sentence; keep a quiet indicator visible for the whole of a legacy session whether or not the stats bar is shown; label failed probes by their real failure. In the app's existing look; check at full size in a dark view and in Space.

2.4 **Medium. On a Mac, saving another preference can erase a newly made key.** Open Settings with no key, turn sharing on (the backend creates a key), change any other preference in the same sheet: the sheet sends back the empty key it loaded, the save rewrites the token, the running host keeps the key in memory and the next launch has none (`apps/sunna/src/sharing/macos.rs:93`, `apps/sunna/ui/main.js:984`, `apps/sunna/src/settings.rs:161`). Check whether Linux has the same path. Fix: key edits get their own command; general preference saves never touch the key file.

2.5 **Medium. Mac readiness stays cached after the display stops delivering.** After one successful test frame the health model skips checks while both permissions stay granted (`apps/sunna/src/mac_host/model.rs:333`). Fix: invalidate on display changes, or give a successful observation a bounded lifetime. Not runnable here: unit tests and the Mac test procedure.

2.6 **Medium. Things already queued in the client can be applied after the connection closed.** A clipboard copy queued in the client can be applied after close, and the audio branch can consume a queued datagram without checking closure (`crates/client/src/lib.rs:782`). Fix: gate queued clipboard and audio delivery on the connection still being open.

2.7 **Medium. Android ends the session at a Linux login handoff.** The host closes with `session changed`; the desktop viewer reconnects (`crates/viewer/src/session.rs:192`); Android runs the client once and stops (`crates/android/src/lib.rs:309`). Fix: the same authenticated reconnect loop on Android, resetting decoder, input, clipboard and audio before the replacement starts.

2.8 **High. The Windows service can store and log the key.** If `--token` is given when installing the service it goes into the service's stored command line, and the console launcher logs the reconstructed command, which can also reach telemetry (`apps/sunnad/src/service.rs:95`, `apps/sunnad/src/main.rs:360`, `apps/sunnad/src/console_session.rs:41`). Fix: never log command lines; refuse credential arguments at service installation and read the key from the protected store. Windows code can't be run here: keep it compiling (cross-check where the toolchain allows) and say so.

2.9 **Tests the review listed as missing** (add them): the relay matrix through the public client and host entry points for every saved-record policy (the transport-level relay test exists at `crates/transport/tests/identity.rs:73`; correct `tools/identity-test/REPORT.md`, which still says it doesn't); an independently computed fingerprint for a known certificate, the same pin after reissuing with the same key, refusal after changing the key, and a bad handshake signature; varying the host nonce length, tag lengths and roles in an otherwise valid exchange, asserting an invalid acknowledgment leaves a record unpinned and sends no operation; a legacy attempt racing the first proof and racing the switch being turned off, across separate processes; a failure injected between the identity file and the record on replacement; restoring an old record file with and without the newer identity file; concurrent identity creation and refusal of a symlinked or wrongly-permissioned identity pair.

2.10 **Docs.** `docs/security.md:12` still describes capture as happening only during a session; the Linux worker and the Mac health check take a short local test frame with no viewer. Say so. Describe pinning, the proof, and the older-computer exception as they now are.
