## 0. Key findings

1. **Sharp text in RDP comes from never relying on the video codec for text.** Windows classifies each frame's non-video pixels as text vs image and sends text through a lossless, cache-heavy codec (ClearCodec: glyph cache + 1-px column caches), images through H.264/RemoteFX, scrolls/moves as client-side blits, and repeats as cache hits. Microsoft's own doc says about 80% of session graphics are text, and that GPU-only "everything is H.264" mode "performs worse than mixed-mode encoding when the screen content is largely text based" (§1.3). Sunna's planned "build-to-lossless static tiles" is the right idea; RDP shows it has to be lossless for text, cached, and scroll-aware to pay off.
2. **Three "refine when idle" mechanisms exist on the wire and all are worth copying in spirit:** RemoteFX Progressive bitplane upgrades, AVC420 per-region QP with a "progressive" flag, and AVC444's "luma now, chroma later" (LC=1 then LC=2). gnome-remote-desktop implements the AVC444 version in production: under motion or throttling it sends main-view only, and 60 ms after motion stops it sends the chroma aux view (`gnome-remote-desktop/src/grd-rdp-surface-renderer.c:37,634-660`).
3. **Apple HP mode already does HEVC 4:4:4 from the media engine on M1/M2** (reverse-engineered: HEVC RExt 4:4:4 8-bit, 4 horizontal strips as separate SSRCs on one bitstream, SRTP/UDP 5901, LTR acks + NACK + FIR, no FEC seen, AAC-ELD audio, TCP RFB control+input). Sunna can't easily beat it on bits-per-pixel on a LAN. It *can* beat it on Wi-Fi/Internet/Tailscale behaviour, input path (HP input rides TCP), resize (HP restarts the encoder and sends an IDR on every resize), session robustness (grey-screen failures), and security (a pre-auth bypass was fixed in Aug 2026) (§5).
4. **Whether public VideoToolbox can encode HEVC 4:4:4 on M1/M2 is the single most important open codec question.** FFmpeg's VT encoder only knows `HEVC_Main42210_AutoLevel` for RExt (`ffmpeg-vt/videotoolboxenc.c:981-985`) and lists no 4:4:4 input formats for HEVC (`:2734-2743`). HP proves the silicon can. It's a 30-minute experiment on the owner's Airs (§3.2). If the answer is no, AVC444-style dual-view on H.264/HEVC 4:2:0 is the fallback that works on every decoder (§1.2).
5. **macOS unattended hosting has two hard blockers, both solvable only with Apple's cooperation or a proper bundle.** (a) On macOS 15+, any non-picker screen capture re-prompts after ~30 days of non-use ("bypass the system private window picker"). Only the managed `com.apple.developer.persistent-content-capture` entitlement or MDM `forceBypassScreenCaptureAlert` removes it. (b) TCC grants are tied to code identity, so the host must be a signed bundle with stable bundle ID and Team ID, never a bare rebuilt binary (§3.3).
6. **CGDisplayStream is dead for Sunna's roadmap.** It is obsoleted in the macOS 15 SDK, it delivers **no frames for CGVirtualDisplay displays on macOS 15+**, and on 15 it appears to be proxied through the same machinery as SCK anyway. The virtual-display plan requires ScreenCaptureKit (§3.1).
7. **Login-window capture on macOS works with SCK from 14.4 on**, from a LaunchAgent with `LimitLoadToSessionType = [Aqua, LoginWindow]` (DTS-confirmed). Never from a LaunchDaemon (§3.4).
8. **On Linux, unattended Wayland hosting has exactly three workable routes:** (a) compositor-private APIs with virtual monitors (Mutter ScreenCast `RecordVirtual` + RemoteDesktop/EIS, which is what g-r-d uses; KWin's `zkde_screencast_unstable_v1`, which is what krdp uses); (b) xdg portals with `persist_mode=2` restore tokens + `ConnectToEIS`, which still need one interactive approval and are backend-dependent; (c) DRM/KMS scanout capture + uinput below the compositor, which RustDesk merged in Aug 2026 as a privileged helper. Sunna needs (a) or (c) for "always available", with (b) as the polite default (§4).
9. **gnome-remote-desktop's Vulkan compute pass is the best zero-copy Linux design in the corpus.** One shader reads the new and previous BGRX dmabuf frames and emits, per 16×16 block, damage flags, the main NV12 view, the AVC444 aux view, and a "chroma needed" flag. VAAPI then encodes straight from the Vulkan images (`gnome-remote-desktop/src/shaders/grd-avc-dual-view.comp`, `grd-rdp-renderer.c:198-225`) (§2.4).
10. **Client presentation on macOS: fullscreen direct-to-display is the only way to skip the WindowServer compositor.** It requires a native fullscreen Space, an opaque `CAMetalLayer`, RGB content, and Apple silicon (Apple doc). An independent macOS 26 measurement found windowed latency to be bimodal (about 42 ms, or 80-122 ms when the compositor is in its slow state) vs 29-55 ms fullscreen (§6.1). Sunna's presenter should be designed for the direct-to-display path and should measure `presentedTime`.

## 1. How RDP's graphics pipeline gets sharp text at low bandwidth

Full detail: `claude-notes/01-freerdp-rdpgfx.md`. Spec: [MS-RDPEGFX] v20260511.

### 1.1 The model: surfaces + a command stream, not "a video"

- RDPGFX runs on a dynamic virtual channel that the spec requires to be **non-lossy** ([MS-RDPEGFX] §2.1 p.14). Every server→client PDU is wrapped in RDP 8.0 bulk compression (ZGFX: LZ77 + static Huffman) ([MS-RDPEGFX] §2.2.5.1 p.72, §3.1.9.1 p.79; `FreeRDP/libfreerdp/codec/zgfx.c`). The generic LZ layer mops up redundancy across commands and planar data.
- The server creates offscreen **surfaces** (client-side bitmaps) and maps them to outputs or windows. Codec output always lands in a surface. Compositing ops are pure client-side commands: `SOLIDFILL` (0x04), `SURFACE_TO_SURFACE` (0x05: scroll/window move in ~20 bytes), `SURFACE_TO_CACHE` (0x06, 64-bit content key) and `CACHE_TO_SURFACE` (0x07, replay to N points) ([MS-RDPEGFX] §2.2.2.4-2.2.2.8 p.22-25).
- `START_FRAME`/`END_FRAME` bracket an atomic present. The client sends `FRAME_ACKNOWLEDGE {queueDepth, frameId, totalFramesDecoded}` **after decoding** ([MS-RDPEGFX] §2.2.2.13 p.27-28). That ack is the flow control (§1.4).
- Caps negotiation (8.0 … 10.7, plus undocumented 11.x "used by Azure") gates AVC420/AVC444, cache size (100 MB / 25,600 slots, or 16 MB / 4,096 slots with SMALL_CACHE/THINCLIENT), and from 10.4 on, **AVC420 mixed with other codecs in the same frame** ([MS-RDPEGFX] §2.2.3.7 p.40-41; `FreeRDP/include/freerdp/channels/rdpgfx.h:108-163`).
- **The cursor is not in the graphics stream at all.** Pointer shapes (up to 384×384, cached, with position updates) go over core RDP pointer PDUs and are drawn locally ([MS-RDPBCGR] §2.2.9.1.1.4), so cursor latency is zero.

### 1.2 Codecs and what each is for

| Codec (id) | Mechanism | Role |
|---|---|---|
| Planar (0x0A) | Per-plane ARGB or AYCoCg (color loss level 0-7, optional 2×2 chroma subsampling), scan-line delta then byte RLE (`FreeRDP/libfreerdp/codec/planar.c:58-67,99-110,196-219`) | Lossless when CLL=0. Cheap on flat UI. |
| **ClearCodec (0x08)** | Three overpainting layers: residual BGR runs; **bands** (≤52 px tall) built from 1-px-wide **V-bars** with a 32,768-entry V-bar cache and a 16,384-entry short-V-bar cache; subcodecs (raw, NSCodec, RLEX palette "run+suite" for AA ramps). Plus a **glyph cache** of 4,000 small bitmaps (≤1024 px²) replayed by a 3-4 byte GLYPH_HIT ([MS-RDPEGFX] §2.2.4.1 p.43-53, §3.3.1.9-13 p.96; `FreeRDP/libfreerdp/codec/clear.c:38-39,455-560,606-880,929-1050`) | **The text codec.** Anti-aliased glyph stems form a small vocabulary of pixel columns, so repeated letters become cache hits at about 2 bytes per column, losslessly. FreeRDP has **no encoder** (`clear.c:1273-1281`); only Windows servers emit it. |
| RemoteFX (0x03) | 64×64 tiles, RGB→YCbCr, 3-level LeGall 5/3 DWT, per-subband quant (factors 6-15, so never lossless), RLGR1/RLGR3 ([MS-RDPRFX] §3.1.8.1 p.33-37) | Intra-only image codec. Sharpness ceiling fixed by the minimum quant. |
| **RFX Progressive (0x09)** | Reduce-extrapolate DWT (no tile seams); coefficient-domain diffs vs what the *decoder* holds; `TILE_FIRST` at a coarse progressive quality, then `TILE_UPGRADE` passes where newly significant coefficients go to an SRL stream and already significant ones get RAW refinement bits (SPIHT/JPEG2000-style bitplanes) ([MS-RDPEGFX] §3.1.8.1 p.75-79, §3.2.8.1 p.88-94, §2.2.4.2.1.5 p.56-66) | **Build-to-quality for static content.** Frame N sends a blurry version; if the region stays static, frames N+1… upgrade it to full (the spec's worked example goes 25%→50%→100%, §4.1.2 p.121-128). FreeRDP's encoder only emits `TILE_SIMPLE` (`progressive.c:2520-2650`), so there's no real refinement. |
| AVC420 (0x0B) | H.264 4:2:0 (High allowed), full-range BT.709. A metablock carries `regionRects` + per-rect `{qp:6, r, p, quality}` ([MS-RDPEGFX] §2.2.4.4 p.67-69, §3.3.8.3.1 p.106) | The decoded frame is **masked by `regionRects`**: only damaged rects are applied to the surface, so static areas never get re-touched by codec noise or drift. The `p` bit marks a progressive (low-QP refresh) pass. FreeRDP damage = 64×64 YUV tile compare (`FreeRDP/libfreerdp/codec/h264.c:244-322`). |
| **AVC444 (0x0E) / v2 (0x0F)** | Two YUV420 pictures from **one** encoder/decoder: the main view (Y444 + 2×2-averaged chroma) is a normal decodable 4:2:0 picture; the aux view packs the remaining chroma samples into the Y/U/V planes of a second picture. v1 interleaves in 8-line blocks inside 16-line MB rows; v2 uses a frame-level half/quarter layout. The client reconstructs the even-even sample as `4·avg − others` only if it differs by ≥30 (anti-noise clip). `LC` field: 0 = both, 1 = main only, 2 = aux only, combined with the previous main ([MS-RDPEGFX] §2.2.4.5-6 p.69-72, §3.3.8.3.2-3 p.109-112; `FreeRDP/libfreerdp/primitives/prim_YUV.c:36-223,355-365`; `prim_internal.h:215-226`) | **4:4:4 on 4:2:0-only hardware codecs.** Also a progressive-chroma mechanism: send LC=1 during motion, then LC=2 when static. Weakness: main and aux pictures alternate in one reference chain, which hurts inter prediction unless long-term refs are used [INFER]. |
| Alpha (0x0C) | Raw or RLE alpha after a colour codec | RAIL windows with transparency. |
| AV1 (0x0001, FreeRDP-private) | libaom encode / dav1d decode, reuses the AVC420 metablock, native **AV1 High I444** (`FreeRDP/libfreerdp/codec/av1.c:29-83`; `rdpgfx.h:108-195`) | FreeRDP's modern replacement for the AVC444 hack. Windows doesn't know it. |

### 1.3 How servers choose per region

- **Windows ("mixed mode").** Per Microsoft's AVD "Graphics encoding over the Remote Desktop Protocol" doc (learn.microsoft.com/en-us/azure/virtual-desktop/graphics-encoding): (1) video detection sends motion-video regions to H.264; (2) the remaining pixels are checked for delta changes, motion (sent as SurfaceToSurface) and cache hits (CacheToSurface); (3) what's left goes to a **text vs image classifier**, where text uses "a custom codec that's optimized for text" (ClearCodec by elimination, UNVERIFIED naming) and images use AVC or RemoteFX. Quote: "On average, approximately 80% of the graphics data for a remote session is text." Mixed mode is **software-encode only**; with GPU encode everything is H.264/HEVC, and "it performs worse than mixed-mode encoding when the screen content is largely text based". AVC444 exists because "text shows a halo effect with typical implementations of AVC/H.264" (MS RDS blog 2016, via FreeRDP issue #3490). HEVC is used on GPU hosts but has no codecId in the public spec, so it presumably rides the undocumented 11.x caps (UNVERIFIED).
- **FreeRDP shadow server:** one codec per session, priority AV1 → AVC444v2 → AVC444 → AVC420 → RemoteFX → Progressive → Planar (`FreeRDP/server/shadow/shadow_client.c:1695-1800`). No classification. H.264 defaults: VBR 10 Mbit/s, 30 fps (`shadow_server.c:1170-1173`).
- **xrdp:** one codec per session (`gfx.toml` order H.264, RFX). x264 `ultrafast/zerolatency/main` with VBV profiles per connection type. AVC420 only; the metablock hard-codes qp=23 (`xrdp/xrdp/xrdp_encoder.c:733-734`).
- **gnome-remote-desktop:** RFX-progressive, AVC420, or AVC444v2 (preferred with HW encode), with a real LC 0/1/2 policy (`gnome-remote-desktop/src/grd-rdp-dvc-graphics-pipeline.c:181-188,530-540,605-660`). See §2.

The open-source servers never reached Windows' per-region classification. **That gap (text-aware, cache-aware, scroll-aware encoding around a hardware video codec) is exactly Sunna's opening on macOS/Linux hosts.**

### 1.4 Caching and flow control

- **Bitmap cache:** the server owns slot allocation, the client is dumb storage. 64-bit content keys allow a **persistent cache across reconnects** via `CACHE_IMPORT_OFFER` (≤5,461 entries) ([MS-RDPEGFX] §2.2.2.16-17 p.30-31, §3.3.1.4 p.95). Useful for re-showing windows and tabs, and for scroll-back.
- **Frame-ack window = implicit congestion + decoder-backpressure control.** Acks arrive after *decode*, so ack RTT = network RTT + decode time, and a window of unacked frames throttles fps when either the network or the client is slow. xrdp: hard window of 2 frames (`xrdp/xrdp/xrdp_mm.c:1337-1350`). FreeRDP shadow: `fps = maxFps/(inFlight+1)` (`FreeRDP/server/shadow/shadow_encoder.c:36-80`). g-r-d: RTT-scaled window (§2.5). Clients may send `SUSPEND_FRAME_ACKNOWLEDGEMENT` to opt out ([MS-RDPEGFX] §3.2.5.13 p.86). QoE acks report client decode and render ms (§2.2.2.21 p.33-34).
- **Transport:** RDP graphics is always reliable and in-order. [MS-RDPEUDP] v1 had a lossy mode and GF(256) FEC over ≤255-packet blocks (§1.3.2.2 p.9-10, §3.1.1.6), but [MS-RDPEUDP2] (current) "only supports reliable UDP mode … does not include an FEC layer" (§3.1.1.1 p.17). So RDP pays head-of-line blocking under loss, which Sunna's datagram design avoids by construction.

### 1.5 Critical assessment for Sunna

- **Steal:** (1) a lossless text/static path with content-addressed caches (glyph/column/tile keys) alongside the hardware video stream; (2) region masks: apply decoded video only inside damaged rects so static text can never be degraded by codec drift; (3) scroll/move as client-side blits of the previous frame (`SURFACE_TO_SURFACE`), fed by motion detection or by SCK dirty rects + move detection; (4) "refine when idle": low-QP or lossless re-send of rects that stayed static for ~60 ms, and progressive chroma; (5) decode-completion acks as a backpressure signal separate from network loss; (6) client-side cursor; (7) AVC444 dual-view as the 4:4:4 fallback when HEVC 4:4:4 decode is unavailable (e.g., Linux VAAPI clients, older Macs).
- **Avoid:** reliable-only graphics transport; DWT codecs (RemoteFX/Progressive) as the primary image codec (hardware H.264/HEVC is far cheaper per bit on moving content, and RFX is never lossless); per-session single-codec designs (FreeRDP/xrdp); AVC444's alternating main/aux reference chain without LTR management.
- **Design sketch [INFER]:** video layer = HW H.264/HEVC over datagrams with region-masked application. Static layer = 64×64 (or 128) BGRA tiles, sent losslessly (e.g., zstd/QOI-style or planar+RLE) once a tile has been damage-free for N ms, keyed by a 64-bit hash into a client LRU cache (also enables `CACHE_TO_SURFACE` replay on window switch), carried on a low-priority reliable QUIC stream. Client composites static tiles over video tiles and invalidates on damage. This is RDP mixed mode rebuilt on top of a modern transport.

## 2. gnome-remote-desktop: architecture and lessons for Linux/Wayland

Source: `gnome-remote-desktop` @ 8ef46be (2026-09-14). g-r-d is GNOME's RDP (and legacy VNC) server. It's the most technically serious open-source Wayland remote-desktop host, and it shows what "doing it right" on Linux takes when you own (or co-own) the compositor.

### 2.1 Process model: three daemon roles + handover

- One binary, three systemd roles (`gnome-remote-desktop/data/*.service.in`): `--system` (system service running as a dedicated user, listens on 3389, no display access), `--handover` (runs inside a headless GDM greeter or user session), and user-mode (`gnome-remote-desktop.service` for sharing an existing session; `--headless` for a user-owned headless session, which `Conflicts=` with the normal one).
- **Remote login flow (GNOME 46+):** an RDP client connects to the system daemon. The system daemon asks GDM (`org.gnome.DisplayManager` RemoteDisplayFactory, `src/grd-daemon-system.c:70-77`) to create a **headless remote display** (a headless mutter greeter). A handover daemon in that session claims the client over the system D-Bus dispatcher (`org.gnome.RemoteDesktop.Rdp.Dispatcher`; `TakeClient`, `grd-daemon-system.c:179-199`). After the user logs in, the connection moves to the handover daemon of the new user session. The move uses an **RDP Server Redirection PDU with a routing token**, so the client reconnects and the system daemon routes it by token (`grd-daemon-system.c:224-353`, `grd-rdp-routing-token.c`). Handover waits have an abort timeout (`abort_handover`, `:206-211`). Sources: [Phoronix: GNOME merges RDP remote login](https://www.phoronix.com/news/GNOME-RDP-Remote-Login), [SUSE: Headless remote sessions in GNOME, part 2](https://www.suse.com/c/headless-remote-sessions-in-gnome-part-2/), [GNOME help: remote login](https://help.gnome.org/gnome-help/remote-login.html).
- Credentials backends: TPM-sealed, libsecret, file, one-time (`grd-credentials-{tpm,libsecret,file,one-time}.c`). Connection throttling: max 5 connections per peer, 5 pending, 10 attempts/s (`grd-throttler.c:28-30`).
- Limitations: remote-login sessions are **separate headless sessions**, not the physical console. "Desktop sharing" of the console session can't unlock a locked screen ([edu4rdshl, 2025-08-29](https://edu4rdshl.dev/posts/solving-the-remote-unattended-access-problem-on-wayland/)). GNOME-only.
- **Lesson [INFER]:** the "system broker + per-session worker + handover" split is the right shape for Sunna's Linux host too. With QUIC, Sunna can do better than a redirect-and-reconnect: the broker can keep the QUIC connection and switch which session worker feeds it (or use QUIC connection migration to a new socket owner), so the login→desktop transition is seamless.

### 2.2 Capture: Mutter ScreenCast (private D-Bus) with virtual monitors

- g-r-d does **not** use xdg-desktop-portal. It talks to Mutter's private `org.gnome.Mutter.ScreenCast` / `org.gnome.Mutter.RemoteDesktop` D-Bus APIs (`src/org.gnome.Mutter.ScreenCast.xml`, `src/org.gnome.Mutter.RemoteDesktop.xml`). There are no permission dialogs, because g-r-d is a trusted system component (in the user session, its enablement is the consent).
- `RecordMonitor(connector, {cursor-mode})` mirrors a physical monitor. `RecordVirtual({cursor-mode, is-platform})` asks Mutter to **create a virtual monitor** sized by the client (`src/grd-session.c:400-456`). The layout manager uses virtual monitors whenever it isn't mirroring. Cursor mode is METADATA (cursor sent separately), except when a virtual monitor *extends* a physical desktop, where it's EMBEDDED (`src/grd-rdp-layout-manager.c:835-863`). Client-driven resize comes through the RDP DisplayControl DVC (`grd-rdp-dvc-display-control.c`, `grd-rdp-monitor-config.c`).
- PipeWire negotiation (`src/grd-rdp-pipewire-stream.c`): BGRx; dmabuf with modifiers when an EGL thread exists **and not on NVIDIA** (NVIDIA falls back to MemFd shared memory, `:536-538`); 2-8 buffers (`:549`); `maxFramerate` = client refresh (`:217-259`); `SPA_META_Header` (checks the CORRUPTED flag, `:1013-1016`); `SPA_META_Cursor` up to 384×384 (`:572-575`); **explicit sync** via `SPA_META_SyncTimeline` when supported (`:540-557, 583`).
- It does **not** use PipeWire's `SPA_META_VideoDamage`. It detects damage itself (§2.3), presumably because compositor damage is coarse or unreliable across clients (UNVERIFIED reason).

### 2.3 Damage detection

- CPU: 64×64 tile memcmp against the previous frame (`src/grd-rdp-damage-detector-memcmp.c:27-28,87-137`).
- CUDA (NVIDIA): damage kernels in `src/grd-cuda-damage-utils.cu:24-112`, shipped as PTX for compute capability 3.0 so Kepler (the first NVENC generation) still works (`data/README.md`).
- **Vulkan (Intel/AMD):** the damage test is fused into the AVC colour-conversion shader. The shader compares new and old frames per 16×16 block (one H.264 macroblock per workgroup, `local_size 16×16`) and writes a damage bitmap plus a "needs auxiliary view" bitmap (`src/shaders/grd-avc-dual-view.comp`, `PERFORM_DMG_DETECTION` spec constant, bindings `DamageBuffer`, `AuxiliaryViewInfoBuffer`). Unchanged frames are not encoded. Damage drives the AVC420 region rects.

### 2.4 Encode paths (exact settings)

| Path | Pipeline | Settings |
|---|---|---|
| **Vulkan + VAAPI** (Intel/AMD) | dmabuf (with DRM format modifiers, `grd-vk-image.c:84-108`; modifier intersection with EGL, `grd-hwaccel-vulkan.c:61-147`) → Vulkan compute (`grd-avc-dual-view.comp`: BGRX → main NV12 + aux NV12 + damage) → **VAAPI encodes directly from the Vulkan-owned images** (VAAPI is created on the Vulkan device, `grd-rdp-renderer.c:198-225`) | H.264 **High**, `VA_RC_CQP`, **pic_init_qp = 22**, `intra_period = 0` (infinite GOP, IDR only on demand), `ip_period = 1` (no B-frames), `max_num_ref_frames = 1`, one slice (`grd-encode-session-vaapi.c:642-647, 923-933, 997, 1695-1705`). g-r-d writes its own SPS/PPS/slice headers (`grd-nal-writer.c`). |
| **NVENC** (NVIDIA) | MemFd buffer → CUDA upload → CUDA kernels for BGRX→NV12/AVC444 views (`grd-cuda-avc-utils.cu:60`) → NVENC | `PROGRESSIVE_HIGH` profile, infinite GOP and IDR period, `frameIntervalP = 1`, quarter-pel MVs, **`NV_ENC_PARAMS_RC_VBR` with `averageBitRate = maxBitRate = 0` and `targetQuality = 22`** (constant quality), full-range BT.709 VUI (`grd-hwaccel-nvidia.c:406-425`). |
| Software fallback | `grd-rdp-sw-encoder-ca.c` (RFX progressive/"CA") | Used when there's no usable GPU (VMs). |

**Observation:** both hardware paths are **constant-quality (QP ≈ 22), not bitrate-targeted**. Bandwidth is controlled by *frame-rate throttling* (§2.5), not by lowering quality. That fits a quality-first desktop product on LANs, but it produces large bitrate spikes on full-screen changes and has no graceful quality degradation on thin links [INFER]. Sunna should keep "quality floor first, then drop fps" as a policy, but with an explicit bitrate cap and QP ceiling.

### 2.5 Graphics pipeline control: AVC444 policy and RTT-aware frame slots

- AVC444v2 is preferred when the client supports it. The view type per frame is DUAL (main+aux), MAIN only, or aux only (`grd-rdp-dvc-graphics-pipeline.c:605-660`).
- **Chroma deferral:** during throttling, or for 200 ms after throttling ends (`TRANSITION_TIME_US`), dual frames are downgraded to main-only (`grd-rdp-surface-renderer.c:45,634-660`). Once content is static, an **aux "frame upgrade" is sent 60 ms later** (`FRAME_UPGRADE_DELAY_US = 60 ms`, `:37, 136-164, 597-628`). This is RDP's "luma now, chroma when still" put into practice.
- **Throttling:** frames are throttled when unacked frames exceed `max(2, min(rtt·fps + 2, fps))` and unthrottled below 1 (`grd-rdp-gfx-frame-controller.c:30-31,110-127`). While throttled, the frame-slot budget is `ack_rate + 2 − enc_rate` (`:177-183`). RTT comes from RDP network autodetect pings every 70 ms (high) / 700 ms (low), averaged over 500 ms (`grd-rdp-network-autodetection.c:28-32`). This is a sensible **ack-clocked, BDP-aware window**: it allows about one RTT's worth of frames in flight plus 2.

### 2.6 Cursor, input, clipboard, audio

- **Cursor:** PipeWire cursor metadata → RDP pointer PDUs with a client-side pointer cache (`PointerCached` fast path, `grd-rdp-cursor-renderer.c:213-248`). The client draws the cursor.
- **Input via libei (EIS)**, not the old `Notify*` D-Bus calls: separate EIS devices for relative pointer, absolute pointer (with regions mapped to streams), keyboard and touch (`grd-session.c:88-121`). Relative motion `ei_device_pointer_motion`, smooth scroll `ei_device_scroll_delta` + `scroll_stop`, discrete scroll `ei_device_scroll_discrete`, keys `ei_device_keyboard_key` + `ei_device_frame` with monotonic timestamps (`:468-700`). **Keyboard layout:** g-r-d reads the EIS keymap fd into an xkb keymap (`setup_xkb_keymap`, `:1252-1314`) and maps keysyms/unicode to keycodes by searching the keymap's levels (`:482-560`), so unicode input works regardless of the host layout.
- Clipboard: RDP CLIPRDR with MIME mapping, lazy format-list-then-data transfer, and a **FUSE filesystem for file copy** (`grd-clipboard-rdp.c`, `grd-rdp-fuse-clipboard.c`).
- Audio: PipeWire capture → RDP audio output with **AAC (fdk-aac) or Opus** or PCM (`grd-rdp-dsp.c:24-55`). Also mic, camera, smartcard redirection.
- View-only mode setting (`grd-session-rdp.c:1868-1901`). Local "a user connected" notifications (`grd-prompt.c`).

### 2.7 What it teaches, and what's weak

- **Copy:** (1) virtual monitors sized to the client, created by the compositor, as the default capture target; (2) dmabuf → Vulkan compute (colour conversion + damage + 4:4:4 split in one pass) → VAAPI with no CPU touch; (3) metadata cursor; (4) libei with keymap-aware keysym injection; (5) the system-broker/handover split for login-screen access; (6) chroma deferral and RTT-scaled ack windows; (7) explicit-sync support in PipeWire negotiation.
- **Weak:** GNOME-only private APIs. RDP over TCP (head-of-line blocking; graphics must be reliable). Constant-QP encode with fps throttling as the only rate control. Session handover is a disconnect + reconnect. The NVIDIA path gives up dmabuf zero-copy (MemFd + CUDA upload). No sharing of a *locked* console session.
- **Portable equivalents:** KDE's **krdp** has two backends: KWin's private `zkde_screencast_unstable_v1` Wayland protocol, which can create **virtual outputs with a DPR** (`krdp/src/PlasmaScreencastV1Session.cpp:175-176`, `screencasting.cpp:159-162`; needs `X-KDE-Wayland-Interfaces=zkde_screencast_unstable_v1` in the .desktop file, `screencasting.cpp:91`), and the xdg portal with `persist_mode = 2` and a stored restore token plus `ConnectToEIS` (`krdp/src/PortalSession.cpp:147-161,216,269`). krdp pauses the encoder when ≥3 frames are queued to send and resumes at 1 (`VideoStream.cpp:50-51`). wlroots compositors: the portal (xdg-desktop-portal-wlr) plus `wlr-virtual-pointer`/`virtual-keyboard` protocols (wayvnc's approach).

## 3. macOS host: APIs, permissions, limitations

Full detail: `claude-notes/03-macos-capture-permissions-service.md` (SCK, TCC, services, audio, clipboard) and `claude-notes/08-deskpad-sudovda.md` (CGVirtualDisplay).

### 3.1 Capture: ScreenCaptureKit is mandatory

- **Legacy APIs are gone for our purposes.** `CGDisplayStream*`, `CGWindowListCreateImage` and `CGDisplayCreateImage` are deprecated in 14.0 and **obsoleted in the macOS 15.0 SDK** ([MacPorts #71136](https://trac.macports.org/ticket/71136)). Rust FFI still links because the symbols remain at runtime, which is why Sunna/RustDesk still run. But on 15+: (a) **CGDisplayStream delivers no frames for CGVirtualDisplay displays** (`CGDisplayStreamStart` succeeds, the callback never fires; tested 15.7) ([rophy/rustdesk #26](https://github.com/rophy/rustdesk/issues/26)); (b) it hangs when two same-named processes use it (`SLSDisplayStreamCreateProxying … timeout`) ([forums 759218](https://developer.apple.com/forums/thread/759218)), which suggests it is now proxied through the SCK/replayd path [INFER]; (c) it's one of the "deprecated content capture technologies" that trigger the Sequoia re-prompt. **The virtual-display roadmap requires SCK.**
- **SCStreamConfiguration settings that matter** ([Apple docs](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration)): `captureResolution = .best` + `width/height` = backing pixels + `scalesToFit = false` for 1:1 Retina. `pixelFormat` is documented as exactly `BGRA`, `l10r`, `420v`, `420f` ([docs](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/pixelformat)). `64RGBAHalf` is used by OBS on 15+ (`obs-studio/plugins/mac-capture/mac-sck-video-capture.m:214-215`), and `xf44` (4:4:4 10-bit biplanar) is reported to work (UNVERIFIED). `queueDepth` defaults to its **minimum of 3, and Apple says don't exceed 8** ([docs](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/queuedepth)); holding surfaces while VT encodes stalls capture. `minimumFrameInterval` caps the rate (use 1/120 for ProMotion clients). `showsCursor = false` (client-side cursor). Set `colorSpaceName`/`colorMatrix` explicitly and signal the same values in the bitstream VUI (colour mismatch is the classic "washed out" bug). HDR: `captureDynamicRange` + HDR presets are **macOS 15** ([WWDC24 10088](https://developer.apple.com/videos/play/wwdc2024/10088/)).
- **SCK is damage-driven.** It delivers only on change. Frames carry `SCStreamFrameInfo.status`, where `.idle` means no new content and **no image buffer** (must not be treated as an error or encoded), plus `.blank`, `.suspended`, `.started`, `.stopped`. Attachments: `displayTime` (mach time of the display refresh, the right capture timestamp), `dirtyRects` (feed the static-tile/region-mask machinery of §1.5), `contentRect`, `contentScale`, `scaleFactor`. OBS uses the latter three for crop (`obs-studio/plugins/mac-capture/mac-sck-common.m:224-247`).
- **Filters:** `SCContentFilter(display:excludingWindows:)` lets the host hide its own overlay windows from the stream. `desktopIndependentWindow` filters follow one window across Spaces, which is the building block for per-app streaming later. `includeMenuBar` (14.2). `SCStream.updateConfiguration`/`updateContentFilter` change resolution without restarting the stream. `SCContentSharingPicker` (14.0) avoids TCC and the re-prompt but needs a local human, so it's useless for unattended hosting.
- **Errors to handle:** `SCStreamErrorUserStopped` (-3817, user clicked stop in the menu-bar indicator), `SCStreamErrorNoCaptureSource` (display removed) (`obs-studio/plugins/mac-capture/mac-sck-common.m:29-49`); permission revoked mid-stream → `didStopWithError`.
- **Implication for Sunna:** as in 07-v1-plan step 3, with two amendments. (1) **Choose pixel format by codec path:** BGRA when feeding the lossless-tile path or a 4:4:4 encoder; `420v` when feeding H.264/HEVC 4:2:0 so SCK's GPU does the conversion (VT's BGRA→YUV conversion is also hardware, so measure both). (2) Treat `.idle` as "no frame" but still schedule quality-refinement work on idle regions.

### 3.2 VideoToolbox: what low-latency actually gives you

Sunna currently sets `EnableLowLatencyRateControl`, `RealTime`, `AllowFrameReordering`, `AverageBitRate`, `ExpectedFrameRate`, `MaxKeyFrameInterval`, `ProfileLevel`, and per-frame `ForceKeyFrame` (`../../crates/codec/src/videotoolbox/mod.rs`).

- **Low-latency mode** (`kVTVideoEncoderSpecification_EnableLowLatencyRateControl`, [WWDC21 10158](https://developer.apple.com/videos/play/wwdc2021/10158/), macOS 12/iOS 15): one-in-one-out (no reordering), a faster-reacting rate controller, always hardware, "up to 100 ms saved" at 720p30. It was announced for **H.264** (plus new Constrained Baseline/Constrained High profiles). FFmpeg enables it for **HEVC only on arm64** (`ffmpeg-vt/videotoolboxenc.c:1709-1721`), which implies HEVC low-latency works on Apple silicon (OS version UNVERIFIED). It **requires an explicit bitrate** (FFmpeg rejects auto bitrate in low-delay mode, `:1711-1715`). When the max QP is hit and the bit budget is exhausted, **the encoder drops frames** (WWDC21). Sunna's "encoder frame drops are normal" commit (0f0b359) matches this.
- **LTR (the IDR-storm killer):** `kVTCompressionPropertyKey_EnableLTR`; the encoder tags frames with `RequireLTRAcknowledgementToken` sample attachments; the app returns acknowledged tokens via the per-frame option `AcknowledgedLTRTokens`; on loss the app sets `ForceLTRRefresh` and the encoder produces a small **LTR-P frame predicted from an acknowledged reference**, falling back to an IDR only if nothing is acked (WWDC21). Apple HP mode uses exactly this (APP-packet LTR acks, §5). This is 07-v1-plan step 6, and it should move earlier: it's the fix for the keyframe re-request storms in commits 01ac41c/d815426.
- **Temporal scalability:** `BaseLayerFrameRateFraction` (e.g. 0.5) and `BaseLayerBitRateFraction` (default 0.6, recommended 0.6-0.8); non-base frames carry `IsDependedOnByOthers = false` and can be dropped by the sender or network with no decode damage (WWDC21). Useful for sender-side drops under congestion without breaking the reference chain.
- **QP and rate controls** (FFmpeg dlsyms them, so they're newer than the baseline SDK: `ffmpeg-vt/videotoolboxenc.c:124-140, 197-220`): `MaxAllowedFrameQP` (1-51, WWDC21), `MinAllowedFrameQP`, `ConstantBitRate` (fails with `kVTPropertyNotSupportedErr` where unsupported, `:1262-1270`), `DataRateLimits` (hard cap; historically unsupported for HEVC on older releases, `:1325-1337`), `PrioritizeEncodingSpeedOverQuality`, `SpatialAdaptiveQPLevel`, `ReferenceBufferCount`. Exact per-property OS versions: UNVERIFIED. The rule: **set each property, check the OSStatus, and log unsupported ones at warn level** (07-v1-plan finding 8).
- **4:4:4:** FFmpeg's VT encoder maps HEVC RExt only to `kVTProfileLevel_HEVC_Main42210_AutoLevel` ("only main42210 is supported", `:981-985`), and its HEVC input list is NV12/420P/BGRA/AYUV/P010/P210, with **no 4:4:4 formats** (`:2734-2743`). 4:4:4 formats appear only for ProRes (`:2745-2775`). But Apple HP's ScreensharingAgent emits **HEVC RExt 4:4:4 8-bit** on M1/M2 (§5.2), so the media engine can. Whether it's reachable through public `VTCompressionSession` is UNVERIFIED. **Experiment (cheap, do first):** on both Airs, dump `VTCopySupportedPropertyDictionaryForEncoder(w, h, kCMVideoCodecType_HEVC, spec)` and look at the `ProfileLevel` supported values (undocumented profile constants show up there, per [forums](https://developer.apple.com/forums/thread/115116) discussion), then encode `kCVPixelFormatType_444YpCbCr8BiPlanarFullRange` frames with each candidate profile and parse the SPS `chroma_format_idc` (3 = 4:4:4). If VT silently subsamples, fall back to AVC444-style dual view (§1.2) or lossless static tiles.
- **Parser gotcha:** on iOS 26 the HEVC encoder started emitting multiple NAL units per frame where it previously emitted one ([forums 799316](https://developer.apple.com/forums/thread/799316)). The packetizer must handle N NALs per sample buffer (and the same may apply to macOS 26, UNVERIFIED).
- **Recommended VT set for Sunna's desktop encoder [INFER from the above]:** low-latency spec + `RequireHardwareAcceleratedVideoEncoder`; H.264 High or Constrained High, or HEVC Main; `RealTime = true`; `AllowFrameReordering = false`; `MaxKeyFrameInterval` = infinite (IDR on demand only); `EnableLTR = true`; `AverageBitRate` from the congestion controller plus `DataRateLimits` at about 1.5× over a 1-frame window if supported; `MaxAllowedFrameQP` ≈ 30-34 for desktop (keeps text legible; let the encoder drop frames instead of smearing) and `MinAllowedFrameQP` ≈ 10-18 (stops wasting bits on static frames); explicit colour primaries/transfer/matrix + full-range tagging; `MaxFrameDelayCount = 0`.

### 3.3 Permissions (TCC) and the unattended-access problem

| Feature | TCC service | Check/request API | Notes |
|---|---|---|---|
| Screen capture | `kTCCServiceScreenCapture` | `CGPreflightScreenCaptureAccess` / `CGRequestScreenCaptureAccess` (`rustdesk/src/platform/macos.mm:28-34`, `Sunshine/src/platform/macos/misc.mm:55-96`) | Prompt shows once; afterwards the user toggles it in Settings and **the process must relaunch** (preflight is cached per process). |
| Posting events (CGEventPost) | **`kTCCServicePostEvent`** (listed under Accessibility; the Accessibility grant also satisfies it) | `CGPreflightPostEventAccess` / `CGRequestPostEventAccess` | Accessibility, PostEvent and ListenEvent are **three independent buckets** (Apple DTS). Without the grant **CGEventPost silently drops events**, so poll the preflight and report it to the client. |
| Listening to local input | `kTCCServiceListenEvent` (Input Monitoring) | `IOHIDCheckAccess`, `CGPreflightListenEventAccess` | Host doesn't need it. The *client* needs it (or Accessibility for filtering taps) to capture Cmd-Tab etc. |
| System audio (Core Audio taps) | `kTCCServiceAudioCapture` ("System Audio Recording Only") | none public | Needs `NSAudioCaptureUsageDescription`. **Without the grant the tap delivers zeros silently.** |
| Clipboard | pasteboard privacy (`NSPasteboard.accessBehavior`, 15.4+) | — | See §3.7. |

- **The Sequoia re-prompt:** "<App> is requesting to bypass the system private window picker and directly access your screen and audio". Weekly + every reboot in 15.0 betas → monthly in 15.0 release → from **15.1 the timestamp refreshes on each use, so it only re-appears after ~30 days of non-use** ([mjtsai](https://mjtsai.com/blog/2024/08/08/sequoia-screen-recording-prompts-and-the-persistent-content-capture-entitlement/), [9to5mac](https://9to5mac.com/2024/08/14/macos-sequoia-screen-recording-prompt-monthly/), [luckman212/screencapture-nag-remover](https://github.com/luckman212/screencapture-nag-remover)). No documented Tahoe change (UNVERIFIED). **Failure scenario:** a Mac reached remotely once a quarter shows the prompt exactly when capture starts, with nobody at the keyboard. Remedies: the managed entitlement **`com.apple.developer.persistent-content-capture`** ("required for a VNC app to have persistent access to screen capture"; request form at developer.apple.com/contact/request/persistent-content-capture; needs a provisioning profile, so an app bundle) ([docs](https://developer.apple.com/documentation/bundleresources/entitlements/com_apple_developer_persistent-content-capture)), or MDM `forceBypassScreenCaptureAlert` (15.1+) ([Der Flounder](https://derflounder.wordpress.com/2024/10/31/managing-user-notifications-for-apps-which-request-screen-access-on-macos-sequoia-15-1/)). MDM **cannot pre-grant** ScreenCapture (only `AllowStandardUserToSetSystemService`); it can pre-grant Accessibility/PostEvent (UNVERIFIED this pass).
- **Responsible-process attribution:** a CLI started from Terminal inherits Terminal's grants (Sunna today). Under launchd the binary itself is the TCC client, identified by its designated requirement: bundle ID + Team ID when Developer ID signed, **path/cdhash when ad-hoc, so every rebuild loses the grant** ([deskhopplus #41](https://github.com/myn/deskhopplus/issues/41)). Ship the agent as a signed `.app` bundle (LSUIElement) with a stable bundle ID and Team ID. `AssociatedBundleIdentifiers` groups it under the main app in Login Items (`rustdesk/src/platform/privileges_scripts/agent.plist:8`).
- **Revocation:** SCStreams stop with an error; CGEventPost silently no-ops. System Settings offers "Quit & Reopen", so the agent needs `KeepAlive`.

### 3.4 Service model, login window, sleep

- **Apple's recommended shape (Quinn/DTS):** a LaunchDaemon for global work (network listener, supervision) and a **per-GUI-session LaunchAgent that captures and posts events**, connected by XPC. "Daemons should not be messing around with GUI stuff, and that includes ScreenCaptureKit" ([forums 814152](https://developer.apple.com/forums/thread/814152), [768146](https://developer.apple.com/forums/thread/768146)).
- **Login window:** agent plist `LimitLoadToSessionType = [Aqua, LoginWindow]` (ignored for daemons). The pre-login instance runs as root in the LoginWindow session. **SCK works pre-login from macOS 14.4** ("we fixed a bug that prevents you from using ScreenCaptureKit in the pre-login context (r.121253782)", thread 814152). RustDesk does exactly this (`rustdesk/src/platform/privileges_scripts/agent.plist:11-14`, `KeepAlive`, `ProcessType = Interactive`), bootstraps into LoginWindow with `launchctl load -S LoginWindow` since there is no `gui/0` domain (`rustdesk/src/platform/macos.rs:1205-1212`), and tracks the console owner via `/dev/console` (`macos.rs:702`).
- **Sunna shape [INFER from the above]:** `Sunna.app` = UI + a root LaunchDaemon (QUIC listener, session broker, pairing keys) + an agent `.app` with `[Aqua, LoginWindow]`, one instance per GUI session. The daemon routes the live QUIC connection to whichever agent owns the console (login → desktop → fast-user-switch) without the client reconnecting (better than g-r-d's redirect, §2.1). Minimum OS for login-window capture: **14.4**.
- **Keeping the host reachable:** hold `IOPMAssertionCreateWithName(kIOPMAssertionTypePreventUserIdleDisplaySleep)` while a session is active; the display sleeping ends SCK frames. Wake the display on connect: RustDesk runs `caffeinate -u -t 5` (declare user activity) (`rustdesk/src/server.rs:239-245`). Hold `PreventUserIdleSystemSleep` while listening only if the user opted into "always available"; otherwise rely on "Wake for network access". MacBooks sleep on lid close unless on power with an external display; whether a CGVirtualDisplay satisfies clamshell mode is UNVERIFIED (test on the Airs).
- **Other runtime bites:** App Nap / timer coalescing: wrap sessions in `NSProcessInfo.beginActivity(options: [.userInitiated, .latencyCritical])`. Run capture/encode/network threads at `QOS_CLASS_USER_INTERACTIVE`. Fanless Airs: the media engine is efficient, but sustained 4K60 plus our own GPU work can thermally throttle; measure over 30-minute sessions (UNVERIFIED magnitude). The menu-bar screen-recording indicator appears whenever capture is active and apps can't hide it (UNVERIFIED whether the persistent-content-capture entitlement changes that).

### 3.5 Virtual displays (CGVirtualDisplay)

- Private ObjC API in CoreGraphics. Classes and fields (`DeskPad/DeskPad/CGVirtualDisplayPrivate.h:15-70`): `CGVirtualDisplayDescriptor` {queue, name, maxPixelsWide/High, sizeInMillimeters, vendorID, productID, serialNum, terminationHandler}, `CGVirtualDisplay` (`initWithDescriptor:`, `applySettings:`, `displayID`), `CGVirtualDisplaySettings` {modes, hiDPI}, `CGVirtualDisplayMode` {width, height, refreshRate}.
- DeskPad usage (`DeskPad/DeskPad/Frontend/Screen/ScreenViewController.swift:24-61`): max 5120×2160, 1600×1000 mm, fake vendor/product/serial (macOS remembers arrangement per vendor/product/serial, so use a **stable serial per client device** to get per-client remembered layouts [INFER]), `hiDPI = 1`, 15 modes at 60 Hz. **The display exists only while the owning process holds the object**, so if the agent crashes the display vanishes and macOS rearranges windows. No entitlement or TCC permission is needed to create one; capturing it needs Screen Recording.
- Apple HP uses the same private SkyLight machinery (`SLVirtualDisplaySettings`, `_SLSDisplaySetDynamicGeometryEnabled`) with **dynamic geometry** for live resize, capped at 3840×2160 backing (§5.3).
- Must be captured with **SCK on macOS 15+** (CGDisplayStream returns nothing, §3.1).
- **Design [INFER]:** isolate it in a runtime-checked module (class exists? selector responds?). Create a HiDPI mode exactly equal to the client view's points × 2 (and 1× fallback). Re-apply settings with a new mode on client resize (debounced), and move the SCK filter to the new geometry with `updateConfiguration`. Pick refresh = client display refresh (60/120). Lease semantics as in SudoVDA (§4.8): the display is tied to agent liveness and the session. Options to make it main / mirror the physical panel use public `CGConfigureDisplayMirrorOfDisplay` / `CGDisplaySetDisplayMode` (Apple HP blanks physical panels when the same user connects, §5.1).

### 3.6 Input injection (host) and cursor

- **Tap locations and sources:** RustDesk posts keyboard with `CombinedSessionState` at the Session tap and notes that mixes physical modifier state (issue #9729), so the HID tap fixes it (`rustdesk/src/server/input_service.rs:713-730`). Sunshine's libvirtualhid uses a `HIDSystemState` source for mouse and a `Private` source for keyboard, posts keyboard at `kCGSessionEventTap` and mouse/scroll at `kCGHIDEventTap` (`libvirtualhid/src/platform/macos/macos_backend.cpp:389-390,497,548-549,710,762`). Use a **private event source** for keyboard so injected modifiers don't leak into (or get polluted by) the local user's state.
- **Double clicks:** set `kCGMouseEventClickState` from the system double-click interval (`rustdesk/libs/enigo/src/macos/macos_impl.rs:174-191`; libvirtualhid `:701`, 500 ms).
- **Scroll:** pixel units + `kCGScrollWheelEventIsContinuous = 1`, scaled by the user's `com.apple.scrollwheel.scaling` (libvirtualhid `:756-762, 31-32`). Use `CGEventCreateScrollWheelEvent2` (non-variadic; Sunna's variadic-FFI bug is in 07-v1-plan) and set the scroll phase and momentum phase fields per event, so apps see native trackpad scrolling with rubber-banding (research/05).
- **Text:** `CGEventKeyboardSetUnicodeString` for characters with no key on the host layout (`rustdesk/libs/enigo/src/macos/macos_impl.rs:429`). Send physical keys as USB HID usages, map to host virtual keycodes, and reserve unicode injection for IME/compose results.
- **Local user interference:** injected events trigger `CGEventSourceSetLocalEventsSuppressionInterval`-style suppression of local hardware input (default about 0.25 s) (UNVERIFIED default); set it to 0 on the injecting source if local and remote users co-drive.
- **Anecdote (macOS 26.5):** from an unsigned daemon, plain keys reached apps but modifier+key combos to a Carbon `RegisterEventHotKey` listener were silently dropped ([nick-liu.com](https://www.nick-liu.com/posts/tahoe-hotkey-dead-end/), single source, UNVERIFIED). Another reason to inject from a signed, TCC-granted agent.
- **Gestures:** no public multitouch injection (research/05). Semantic replay plus private gesture CGEvents is the ceiling on physical Macs.
- **Cursor for the client-side cursor channel:** RustDesk detects changes with private `CGSCurrentCursorSeed()` and reads image and hotspot from `[NSCursor currentSystemCursor]` (`rustdesk/src/platform/macos.rs:62,565-640`). Poll the seed cheaply at 60-120 Hz and send shape only on change.

### 3.7 Audio and clipboard

- **Audio:** Core Audio process taps (API 14.2, reliable from 14.4): `CATapDescription initStereoGlobalTapButExcludeProcesses:` + `AudioHardwareCreateProcessTap` + a private aggregate device with `kAudioAggregateDeviceTapListKey`. `muteBehavior = CATapMuted` silences the host speakers while streaming, with no virtual driver (`Sunshine/src/platform/macos/av_audio.mm:629-699`; [AudioCap](https://github.com/insidegui/AudioCap)). Separate TCC service, so presumably no Sequoia re-prompt [INFER]. Detect the silent-zeros failure by RMS == 0 for N s. SCK audio (13.0+) is the fallback and is covered by the Screen Recording grant.
- **Clipboard:** poll `NSPasteboard.changeCount` (no notification API; reading changeCount didn't alert in testing). macOS 15.4 introduced **pasteboard privacy** (`NSPasteboard.accessBehavior`: default "ask upon programmatic access"; `detectPatterns/Metadata/Values` inspect without alerting; opt-in via `EnablePasteboardPrivacyDeveloperPreview`) and Apple said enforcement comes "in a future release" ([mjtsai](https://mjtsai.com/blog/2025/05/12/pasteboard-privacy-preview-in-macos-15-4/), [lapcat](https://lapcatsoftware.com/articles/2025/5/3.html)). Not enforced by default in 26 as of mid-2026 (UNVERIFIED). **Design:** announce available types (lazy, RDP CLIPRDR-style), fetch contents only when the peer pastes, never sync `org.nspasteboard.ConcealedType`/`TransientType`, and plan for a one-time "Allow" in Privacy & Security.

- **Privilege for KMS:** `CAP_SYS_ADMIN` is required for `drmModeGetFB2` to return handles of other clients' framebuffers. Sunshine ships `setcap cap_sys_admin,cap_sys_nice+p` (`Sunshine/cmake/packaging/linux.cmake:84-86`) and raises the capability only around the privileged calls (`kmsgrab.cpp:47-66`). **RustDesk's merged design** (PR #15420, merged 2026-08-06): a separate `drmtap-helper` with only `CAP_SYS_ADMIN`, `PR_SET_NO_NEW_PRIVS`, a ~20-syscall default-KILL seccomp allowlist, frames passed as dmabuf fds over a socketpair. **EGL detiling stays in the unprivileged process.** Separate `--uinput-service` for input. Tested on Intel i915 (CCS detile + VAAPI), AMD, NVIDIA Jetson, virtio-gpu (linear FB). Capped at about 60 fps (16 ms min interval), cursor polled asynchronously. Open concerns: a world-executable capability binary lets any local user read other sessions' scanout (recommend mode 0750 + group), and HiDPI cursor scaling ([rustdesk PR #15420](https://github.com/rustdesk/rustdesk/pull/15420), [discussion #15417](https://github.com/rustdesk/rustdesk/discussions/15417), [blog](https://rustdesk.com/blog/unattended-remote-access-wayland/)). Background: the portal requires "a real user to approve it through a dialog box, every time, from an active session" in RustDesk's portal mode ([discussion #13902](https://github.com/rustdesk/rustdesk/discussions/13902)).
- **KMS caveats [INFER + Sunshine experience]:** it needs a lit CRTC (a real or dummy monitor, or an EDID override via `drm.edid_firmware=`/`video=` kernel params, or `vkms`). It captures whatever is scanned out (no per-window capture, no virtual monitor sized to the client unless you also create one). There's no damage information, so capture is polling. NVIDIA needs `nvidia-drm.modeset=1`. And it breaks the Wayland security model on purpose, so it has to be opt-in and privilege-separated.
- **PipeWire details worth copying from g-r-d (§2.2):** request dmabuf with modifiers and fall back to MemFd; 2-8 buffers; `maxFramerate` = client refresh; `SPA_META_Header` (drop CORRUPTED); `SPA_META_Cursor` up to 384²; explicit sync (`SPA_META_SyncTimeline`) when the EGL/Vulkan stack supports it. Use the portal's `pipewire-serial` (v6) rather than node IDs for targeting (`ScreenCast.xml:278-286`).

### 4.2 Input injection options

- **libei / EIS:** the compositor hands out an EIS socket (portal `ConnectToEIS`, or Mutter's private RemoteDesktop). Devices are negotiated per capability (relative pointer, absolute pointer with regions, keyboard **with the compositor's keymap fd**, touch, smooth and discrete scroll + scroll-stop). g-r-d's use is a complete reference (§2.6, `gnome-remote-desktop/src/grd-session.c:88-121,468-700,1252-1314`). Support: Mutter 45+, KWin 6.1+ via portal (UNVERIFIED exact versions), Hyprland's portal (in progress, [xdph PR #402](https://github.com/hyprwm/xdg-desktop-portal-hyprland/pull/402)); **xdg-desktop-portal-wlr has no libei** ([xdpw #323](https://github.com/emersion/xdg-desktop-portal-wlr/issues/323)), so wlroots compositors use `zwlr_virtual_pointer_v1` / `zwp_virtual_keyboard_v1` directly. Rust bindings: `reis` (cloned at `/home/sunny/research-repos/reis`).
- **uinput** (`/dev/uinput`): kernel-level virtual devices. The compositor sees them as hardware, so they work on every compositor, **at the login screen**, and in any session. The costs: root or a udev rule granting an `input`/`uinput` group, keycodes only (the host's layout applies, so client and host layouts must be reconciled), pointer acceleration applied to relative devices, and absolute pointers need a device-to-screen mapping. inputtino (Wolf) creates, among others, a **virtual multitouch trackpad** with `ABS_MT_SLOT`, `BTN_TOOL_QUINTTAP`, `INPUT_PROP_POINTER | INPUT_PROP_BUTTONPAD` (`inputtino/src/uinput/trackpad.cpp:42-71`), plus touchscreen (`INPUT_PROP_DIRECT`, `touchscreen.cpp:39-63`) and pen tablet. **This is the path to native GNOME/KDE touchpad gestures from a Mac client's trackpad**: libinput should classify such a device as a clickpad and run its own gesture recognizer (end-to-end UNVERIFIED; test on the Linux VM). It's the Linux counterpart to research/05's "raw contacts on the wire".
- Recommended: **libei when a compositor session is available and consented; uinput via a tiny privileged helper for the greeter/unattended path and for multitouch trackpad fidelity.**

### 4.3 Headless and virtual displays

- **GNOME:** Mutter virtual monitors via `RecordVirtual` (client-sized, HiDPI-capable) in a normal or headless session. `gnome-remote-desktop --headless` user service. System-level remote login via GDM remote displays (§2.1). Mutter also has a `--headless` / `--virtual-monitor WxH` developer mode (UNVERIFIED flag spelling in current releases).
- **KDE:** `zkde_screencast_unstable_v1.stream_virtual_output(name, w, h, dpr, cursor_mode)` (`krdp/src/screencasting.cpp:159-162`). KWin also has a virtual backend (`kwin_wayland --virtual`, UNVERIFIED flag).
- **wlroots:** `WLR_BACKENDS=headless` + `swaymsg create_output` creates arbitrary headless outputs.
- **Nested/owned compositor:** Wolf runs each client in its own Smithay-based Wayland compositor (and gamescope for games), so capture, input and resolution are fully owned (see Astra's dossier §4). This is the cleanest route to "no consent problem" for *new* sessions, but it can't show the user's existing desktop.
- **Kernel-level:** `vkms` / EVDI (DisplayLink virtual connectors) / EDID-forced connectors make KMS capture possible on headless boxes.
- **VM hosts (the owner's Linux VM):** virtio-gpu gives a linear framebuffer, which KMS capture handles (RustDesk tested it). With no GPU encoder, use **x264 `tune=zerolatency`** (ultrafast/superfast; 4:4:4 via High 4:4:4 Predictive is possible in software) or openh264. Budget CPU carefully; the lossless static-tile path matters even more here, because desktop content is mostly static.

### 4.4 Encoding on Linux

- **Zero-copy pipeline pattern (from g-r-d):** dmabuf (with modifier) → Vulkan import (`VK_EXT_image_drm_format_modifier`, `grd-vk-image.c:84-108`) → one compute pass (colour convert + damage + optional 4:4:4 split) → VAAPI encode from the same device (`grd-rdp-renderer.c:198-225`). g-r-d's encode settings: H.264 High, CQP 22, infinite GOP, 1 ref, no B-frames (`grd-encode-session-vaapi.c:642-647,923,1695-1705`).
- **NVIDIA:** g-r-d abandons dmabuf on NVIDIA and uses MemFd + CUDA upload (`grd-rdp-pipewire-stream.c:536-538`). Sunshine uses an EGL→CUDA interop path (see Astra §1.2). Vulkan Video encode (`VK_KHR_video_encode_h264/h265/av1`) is the vendor-neutral future. Moonshine already uses it (Astra §5); driver maturity varies (UNVERIFIED for 2026 Mesa/NVIDIA status).
- Rate control: prefer VBR/CBR with a cap driven by Sunna's congestion controller over g-r-d's constant-QP. Use low-power `VAEntrypointEncSliceLP` on Intel where available; intra-refresh and ROI support vary by driver (UNVERIFIED per-driver matrix).

### 4.5 Audio and clipboard

- Audio: PipeWire monitor of the default sink; in headless sessions create a null sink (`pactl load-module module-null-sink`). g-r-d captures from PipeWire and encodes AAC/Opus (`grd-rdp-dsp.c:24-55`).
- Clipboard: GNOME doesn't implement `wlr-data-control`/`ext-data-control-v1`, so a non-focused daemon must use the **Clipboard portal** (v1: `RequestClipboard` before Start, then `SetSelection` / `SelectionRead` / `SelectionWrite` over MIME-typed fds, `xdg-desktop-portal/data/org.freedesktop.portal.Clipboard.xml:20-60,90-167`) or Mutter's private API. wlroots and KWin offer data-control protocols.

### 4.6 Recommended Linux host architecture [INFER]

1. `sunnad` system service (root or a dedicated user with narrowly scoped helpers): QUIC listener, pairing, session broker.
2. Per-session worker in the user's session. Tries, in order: compositor-private virtual monitor (Mutter RecordVirtual / KWin zkde) → portal ScreenCast+RemoteDesktop with `persist_mode = 2` and stored restore tokens + EIS → KMS fallback. Input: EIS, else uinput.
3. Greeter/unattended mode: KMS capture helper (RustDesk-style privilege separation) + uinput helper, opt-in at install time, group-restricted.
4. Capture → Vulkan compute (convert/damage/tiles) → VAAPI/NVENC/Vulkan Video, or x264 in VMs.

### 4.7 Windows (brief; other researchers cover the engines)

- **DDA vs WGC:** Desktop Duplication (`IDXGIOutputDuplication`) gives dirty rects and **move rects** (`GetFrameDirtyRects`/`GetFrameMoveRects`, the same "scroll as a blit" signal RDP uses) and the pointer shape separately (`GetFramePointerShape`). It needs to run in the interactive session (a SYSTEM service + session-switching for the secure desktop/UAC) and has hybrid-GPU pitfalls. Windows.Graphics.Capture is per-window capable, draws a yellow border unless `IsBorderRequired = false` (Win11), and has a minimum update interval setting. (General knowledge; UNVERIFIED specifics. See Astra §1.2 for Sunshine's actual choices.)
- **IddCx virtual displays (SudoVDA)**, detail in `claude-notes/08-deskpad-sudovda.md`: a UMDF driver with an IOCTL control plane — `ADD_VIRTUAL_DISPLAY {Width, Height, RefreshRate, MonitorGuid, DeviceName, SerialNumber}` → `{AdapterLuid, TargetId}`, `REMOVE`, **`SET_RENDER_ADAPTER`** (pin the IDD to the encoding GPU), `GET_WATCHDOG`, `PING` (`SudoVDA/Common/Include/sudovda-ioctl.h:10-64`). **Watchdog lease:** any IOCTL resets a countdown (default 3 s), and at zero all virtual monitors are unplugged (`SudoVDA/Virtual Display Driver (HDR)/SudoVDA/Driver.cpp:380-400,1488-1491`). Apollo pings every timeout/3 (`Apollo/src/platform/windows/virtual_display.cpp:601-618`). EDID is generated per monitor with the preferred mode spliced in (`Driver.cpp:845-900`). HDR via IddCx 1.10 callbacks + FP16 (`Driver.cpp:487-499,795-796`; fully on Win11 24H2 only). A hardware cursor is declared (`IddCxMonitorSetupHardwareCursor`, `Driver.cpp:955-975`), so the OS doesn't bake the cursor into the surface. The driver discards swapchain frames; the streamer captures via DDA/WGC (`Driver.cpp:720-760`).
- **Lesson for all three OSes:** virtual displays should be **leases** that die with the host process or session, not persistent objects that can strand the user's desktop on an invisible monitor.

## 5. Apple Screen Sharing High Performance mode: what it is and where it's weak

Full detail, including a reverse-engineering and benchmark procedure for the owner's Airs: `claude-notes/05-apple-screen-sharing-hp.md`. Tags: [DOC] Apple-documented, [RE] community reverse engineering, [INFER] mine.

### 5.1 What Apple documents

[DOC] ([ARD guide: Use High Performance screen sharing](https://support.apple.com/guide/remote-desktop/use-high-performance-screen-sharing-apdf8e09f5a9/mac), [Mac User Guide: screen sharing type options](https://support.apple.com/en-gb/guide/mac-help/mchl1883115d/mac)):
- Both ends Apple silicon + macOS 14+. UDP 5900-5902 must be reachable (plus TCP 5900).
- **75 Mbps per 4K display**, "consistent low network latency", **wired recommended**.
- One or two **virtual displays**, max 4K or 1080p HiDPI, dynamic resolution matching the viewer window.
- 4:4:4 chroma, HDR reference mode (requires the "HDR Video (P3-ST 2084)" preset), 30/60 fps, stereo audio.
- **One HP session per Mac.** The host's physical displays are blanked when the viewer logs in as the same user.
- Standard mode "adapts resolution and frame rate to network conditions". HP apparently doesn't degrade the same way.

### 5.2 How it actually works

The best source is [iShareScreen](https://github.com/renegadelink/iShareScreen) (AGPL, a cross-platform HP *client*) and its RFC-style spec [`docs/apple_vnc_rfc.md`](https://github.com/renegadelink/iShareScreen/blob/main/docs/apple_vnc_rfc.md), derived from pcaps and disassembly of `screensharingd`, `ScreensharingAgent`, `ScreenSharing.framework` and `AVConference`. High quality, but not Apple-confirmed. [RE]:
- **Control plane:** Apple RFB `003.889` on TCP 5900. Auth types 30 (DH-1024, legacy), 33 (RSA-2048 envelope + SRP-6a 4096/SHA-512), 35 (Kerberos), 36 (SRP). Then an **AES-128-CBC record layer with a plain SHA-1(seq‖plaintext) trailer (not HMAC)**, no server authentication beyond TOFU of an RSA key, downgradable. Input (X11 keysyms, keyboard-layout sync), clipboard (zlib multi-flavour pasteboard archive, fetched on demand), **cursor shapes with a store/select cache drawn locally by the viewer**, and virtual-display config all ride this TCP channel.
- **Virtual display:** client sends `SetDisplayConfiguration (0x1d)` with a mode table (backing vs scaled size, refresh, HDR flag, dynamic-resolution flag). `ScreensharingAgent` creates it via SkyLight (`SLVirtualDisplaySettings`, `_SLSDisplaySetDynamicGeometryEnabled`) and replies with `AppleDisplayLayout (0x451)`. Backing capped at 3840×2160. **Every resize = new media offer + encoder restart + new SSRC group + VPS/SPS/PPS + IDR** (no TCP reconnect).
- **Media plane:** an **AVConference (FaceTime stack) session** negotiated through opaque offer blobs (`AVCMediaStreamNegotiator`). Video: **HEVC Range Extensions 4:4:4 8-bit** (with an H.264 4:2:0 fallback bank) over **SRTP AES-256-CM / HMAC-SHA1-80 on UDP 5901**. Each frame is **split into 4 horizontal strips sent as separate SSRCs but forming one HEVC bitstream with cross-strip references** (one decoder; IDR only on the base SSRC). Non-standard RFC 7798 variant (DONL on every packet). Audio: **AAC-ELD stereo, ~21-24 kbps** + RTCP on UDP 5900. Offer tiers include 6/20/40/60 Mbps plus "HP tiers" 75 and 100 Mbps.
- **Loss recovery:** RTCP FIR (legacy PT 192) for keyframes, **APP (PT 204, subtype 5) LTR acknowledgements**, and the server honours AVPF generic **NACK and retransmits**. **No FEC was observed.** Observed peaks: about 300 Mbps / 28k packets/s for a HiDPI 2× stream under load (bursty; iShareScreen needed a 16k-packet queue) (UNVERIFIED as a controlled measurement).
- **Fallback:** if the media offer fails, the session silently stays on legacy TCP framebuffer codecs (zlib, Apple 0x3e8-0x3f3 tile/DCT codecs).

### 5.3 Where it's weak (and what that means for the owner's test)

- **Designed for wired LANs.** Apple's own guidance is wired + consistently low latency. An RTC stack tuned for calls backs off on Wi-Fi jitter [INFER]. The owner's M1↔M2 Air test over Tailscale on Wi-Fi was outside the design envelope, which matches his "not even that good".
- **Recovery is RTT-bound.** NACK retransmit and FIR/IDR cost at least one RTT. On Tailscale/DERP paths (50-150 ms) with large 4:4:4 IDRs, that means freezes and grey patches. User reports of **grey screen with working cursor** ([Apple Community 255291758](https://discussions.apple.com/thread/255291758)) and one-way failures ([MacRumors](https://forums.macrumors.com/threads/high-performance-screen-sharing-mode-works-only-one-way.2431136/)) fit a media-path failure while the TCP control path (cursor, input) keeps working [INFER].
- **Input rides TCP**, inside a CBC record stream behind clipboard/control traffic, so it suffers head-of-line blocking under loss.
- **Resize hitches** (encoder restart + IDR on every resize). Session transitions (lock, login, fast user switch) mean an agent handoff and stream re-arm.
- **Wi-Fi AWDL stalls:** AWDL (AirDrop/Continuity) periodically parks the radio, causing about 50-100 ms stalls roughly every second ([gist](https://gist.github.com/kouwei32/c101be682fc2e433e153ea131798caec), COMMUNITY). This affects HP *and* Sunna, so benchmarks must record AWDL state.
- **VPN fragility:** HP breaks over sing-box's Tailscale endpoint but works over the official client on the same path ([sing-box #4155](https://github.com/SagerNet/sing-box/issues/4155)). Fixed well-known ports make NAT and remapping awkward.
- **Hard limits:** 4K / 60 fps / 2 displays / one session / Mac-only viewer.
- **Security:** pre-auth Screen Sharing authentication bypass fixed in **macOS 26.6.1 / 15.7.9 / 14.8.9** (Aug 2026), reported exploited ([Macworld](https://www.macworld.com/article/3214311/macos-tahoe-26-6-1-fixed-a-pretty-major-screen-sharing-flaw.html), [MacRumors](https://www.macrumors.com/2026/08/17/macos-screen-sharing-flaw-exploited/)). Plus the dated crypto design above.
- **Regressions:** "unable to start a High Performance connection" on macOS 26 beta ([forums 789695](https://developer.apple.com/forums/thread/789695)). Clicks on the second display landing on the first ([MacRumors](https://forums.macrumors.com/threads/screen-sharing-high-performance-mode-2-screen-not-working-with-separate-windows.2430426/)).
- **No public click-to-photon numbers exist for HP.** 9to5Mac on gigabit Ethernet: "almost … like I'm controlling the Mac natively", no numbers ([9to5Mac 2026-02-05](https://9to5mac.com/2026/02/05/how-to-use-macos-high-performance-screen-sharing-for-lower-latency-and-better-color-video/)). Sunna publishing a rigorous benchmark is itself a differentiator.

### 5.4 Where Sunna can and can't beat it [INFER]

- **Hard to beat on a clean wired LAN:** image quality per bit (HEVC 4:4:4 from the media engine), macOS integration (SkyLight virtual displays, audio, clipboard, no install).
- **Beatable:** (1) latency *consistency* on Wi-Fi/Internet (FEC + deadline-aware NACK + LTR instead of FIR; pacing-aware congestion control); (2) input on unreliable/priority datagrams; (3) seamless resize (scale during drag, commit on release, or keep a larger virtual display and crop); (4) session robustness (no grey screen: always recover from a known-good LTR); (5) sharp text even at low bitrate (lossless static tiles, which HP lacks because it's pure video); (6) modern crypto (QUIC/TLS 1.3 + pinned keys); (7) non-Mac viewers.
- **Copy from HP:** strip/slice-parallel encode on one bitstream; LTR-ack recovery; local cursor with a shape cache; a virtual display per client window with a dynamic mode table; blanking physical panels for privacy.
- **Benchmark protocol:** 5.4-5.5 of the notes: USB-HID microcontroller + photodiode (or 240 fps camera) on the viewer, host test app that flips black/white on mousedown and on keydown, ≥200 trials per condition, ABAB alternation; conditions LAN-direct / Tailscale-direct / DERP, Wi-Fi vs Ethernet, AWDL on/off, Network Link Conditioner loss/delay; metrics p50/p95/p99, frame drops, bitrate (tcpdump on the utun + WireGuard outer port), coloured-text fidelity, resize hitch, recovery time after a 2 s Wi-Fi drop.

## 6. Client-side rendering for minimum latency and maximum sharpness

Full detail: `claude-notes/07-client-rendering.md`. Astra's dossier §2.2-2.4 covers moonlight-qt's decoder matrix and pacer. This section adds platform presentation facts and sharpness.

### 6.1 macOS

- **Direct-to-display is the prize.** Apple: "To enable direct-to-display, your app needs to run in full-screen mode, displaying an opaque CAMetalLayer and RGB content, and run on a Mac with Apple silicon … verify with the Metal HUD or Instruments". The hardware then scales non-matching drawables "with a high-quality upscaling or downscaling algorithm" ([Managing your game window for Metal in macOS](https://developer.apple.com/documentation/metal/managing-your-game-window-for-metal-in-macos)). Independent measurement on macOS 26 (Intel 16" MBP, pointer→`presentedTime`): windowed is **bimodal, ~42 ms or 80-122 ms** depending on an unidentified compositor state; fullscreen Space **29-55 ms in both states**; "Direct scan-out is chosen by macOS, not guaranteed" ([systemless #1050](https://github.com/benletchford/systemless/issues/1050)).
- **Present-mode trade-offs:** a community low-latency recipe is `displaySyncEnabled = isFullscreen; maximumDrawableCount = 2; presentsWithTransaction = YES; opaque = YES; wait until the last moment to sample` ([Daniel Hooper](https://x.com/DanielcHooper/status/2067320915545686158)). Apple forums counter that 2 drawables is "basically impossible to make work with the macOS compositor" (an M1 Max at 120 Hz got about 80 Hz), and DTS recommends **`CAMetalDisplayLink`** (macOS 14+) ([forums 763426](https://developer.apple.com/forums/thread/763426)). `displaySyncEnabled = NO` costs kernel CPU (InterruptEventSourceBridge) ([forums 761635](https://developer.apple.com/forums/thread/761635)).
- **What moonlight-qt does:** vsync on + Apple silicon + macOS 14 → `CAMetalDisplayLink` with `preferredFrameLatency = 1.0`, latest-frame-wins, waits up to half a frame for a fresh frame (`moonlight-qt/app/streaming/video/ffmpeg-renderers/vt_metal.mm:598-613,811-821,913-935`). Vsync off → `nextDrawable` → present → commit → **`waitUntilCompleted` on the render thread** (`:566-572,617-624`). Bilinear sampling for everything (`moonlight-qt/app/shaders/vt_renderer.metal:18`). Per-frame colourspace tagging of the layer (`vt_metal.mm:230-254`).
- **Sunna presenter [INFER]:** dedicated present thread. Decode to IOSurface NV12 (or `x420`), import with `CVMetalTextureCacheCreateTextureFromImage`, convert YUV→RGB in our shader into a BGRA drawable (direct-to-display requires RGB). Two A/B-able modes: **arrival** (present on decode, sync off, fullscreen only) and **display-link** (CAMetalDisplayLink, latest-frame-wins, render as late as possible). `maximumDrawableCount` 3 by default, 2 measured. Never `waitUntilCompleted`; release textures in `addCompletedHandler`. Report `MTLDrawable.presentedTime` as the true end of the pipeline (07-v1-plan step 1 should use it).
- **Decode:** `VTDecompressionSession` defaults to real-time priority ([docs](https://developer.apple.com/documentation/videotoolbox/kvtdecompressionpropertykey_realtime)). Don't set `EnableTemporalProcessing`. Keep streams B-frame-free with VUI `max_num_reorder_frames = 0` (moonlight patches SPS for exactly this on macOS, Astra §2.2).

### 6.2 Sharpness rules (all platforms)

1. **No resampling:** make the host virtual display equal to the client drawable in pixels (points × backingScaleFactor), set `drawableSize` to the stream size, and align texel centres exactly. A half-pixel offset with a linear sampler blurs every glyph. Use nearest sampling when 1:1.
2. **During window drags,** scale with a good filter (bicubic/Lanczos, or let direct-to-display hardware scale in fullscreen), then ask the host to resize (debounced) and return to 1:1. This is also how to avoid HP's per-resize IDR hitch.
3. **4:2:0 fringes coloured text.** Use siting-correct bilinear chroma upsampling (H.264 default chroma siting "type 0" is left-centre; nearest is worse). Better: 4:4:4 (HEVC RExt where decodable; AVC444-style aux view recombined in the shader, §1.2). Best for static content: lossless tiles composited over the video (§1.5).
4. **Colour management:** tag the layer colourspace to match the encode tagging (sRGB vs Display P3; Macs are P3). Output gamma-encoded values to `bgra8Unorm` with the right colourspace; don't double-apply sRGB.

### 6.3 Client input on macOS (latency-relevant)

- Set `NSEvent.isMouseCoalescingEnabled = NO` so every mouse sample is delivered, not one per frame.
- Pointer lock: `CGAssociateMouseAndMouseCursorPosition(false)`.
- System shortcuts (Cmd-Tab/Space/Mission Control) need an active `CGEventTap` with client-side Accessibility while focused; make it opt-in with an escape chord (research/05).
- **Local hardware cursor** drawn from host-sent shapes (`NSCursor`) for zero-latency pointer feel. HP, RDP and g-r-d all do this.

### 6.4 Linux and Windows clients

- **Linux:** VAAPI/Vulkan decode → dmabuf → EGL/Vulkan import, or attach the dmabuf to a `wl_subsurface` via `linux-dmabuf-v1` (v4 scanout tranches) for overlay-plane presentation without composition. Presentation timing: `presentation-time` feedback, `tearing-control-v1` for async flips, `fifo-v1` + `commit-timing-v1` (wayland-protocols 1.38, Oct 2024) ([Phoronix](https://www.phoronix.com/news/Wayland-Protocols-1.38)). SDL only prefers Wayland when fifo-v1 exists ([SDL #11640](https://github.com/libsdl-org/SDL/pull/11640)). Kiosk/handheld: DRM atomic commit to a plane (moonlight `drm.cpp`, Astra §2.2).
- **Windows:** D3D11VA → flip-model swapchain (`FLIP_DISCARD`), frame-latency waitable + `SetMaximumFrameLatency(1)`, `ALLOW_TEARING` + `Present(0, DXGI_PRESENT_ALLOW_TEARING)`, independent flip/MPO in borderless fullscreen ([flip model](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/for-best-performance--use-dxgi-flip-model), [waitable swap chains](https://learn.microsoft.com/en-us/windows/uwp/gaming/reduce-latency-with-dxgi-1-3-swap-chains)).
- **wgpu:** zero-copy import is possible only through HAL escape hatches (wgpu 30 added `texture_from_dmabuf_fd`; crates like [wgpu-external-frame](https://github.com/water-rs/wgpu-external-frame) wrap IOSurface/dmabuf/shared handles). `NV12` may be reported unsupported on Metal ([wgpu #6921](https://github.com/gfx-rs/wgpu/issues/6921)), so import planes as R8/RG8. wgpu exposes no `presentedTime`, `CAMetalDisplayLink`, DXGI waitables or Wayland presentation feedback. This confirms 07-v1-plan: raw CAMetalLayer on macOS, and wgpu or raw Vulkan/D3D11 elsewhere behind a presenter trait that must report a real present timestamp.

| S2 | **Region-masked video application**: apply decoded video only inside damaged rects | AVC420 `regionRects` ([MS-RDPEGFX] §2.2.4.4) | Static text can't be smeared by codec drift or noise between refreshes. |
| S3 | **Scroll/move as client-side blit** (copy the previous frame region, encode only the exposed strip) | RDP `SURFACE_TO_SURFACE`; DDA move rects (§1.1, §4.7) | Scrolling is the dominant desktop motion; cheaper and sharper than motion-compensated video at low bitrate. Detect by row-hash matching on SCK dirty rects. |
| S4 | **Refine when idle**: low-QP or lossless refresh ~60 ms after a region stops changing; progressive chroma (luma-only during motion, chroma catch-up when still) | RFX Progressive, AVC420 `p` flag, AVC444 LC=1→2; g-r-d `FRAME_UPGRADE_DELAY_US = 60 ms`, chroma deferral during throttling (`grd-rdp-surface-renderer.c:37,45,634-660`) | Motion stays cheap and smooth; stills converge to perfect. |
| S5 | **LTR-ack recovery instead of IDR**, keyframe as last resort | VT LTR (WWDC21); Apple HP APP-packet LTR acks (§5.2) | Directly fixes the keyframe re-request storms Sunna has been fighting (commits d815426, 01ac41c). Move 07-v1-plan step 6 earlier. |
| S6 | **Temporal-layer encode** (`BaseLayerFrameRateFraction`) so the sender can drop enhancement frames under congestion without breaking references | VT (WWDC21) | Makes sender-side frame dropping safe by construction (07-v1-plan bug #1 class). |
| S7 | **Ack-clocked, RTT-scaled frames-in-flight window**, acked after *decode* | RDP frame acks; g-r-d `max(2, min(rtt·fps+2, fps))` (`grd-rdp-gfx-frame-controller.c:110-127`); xrdp window 2 | Couples encoder rate to both network and client decode speed; complements delay-based bitrate control. |
| S8 | **Slice/strip-parallel encode on one bitstream** | Apple HP 4-strip SSRCs with cross-strip refs (§5.2) | Pipeline encode → packetize → send at sub-frame granularity; lower glass-to-glass latency on 4K. |
| S9 | **Client-side cursor with a shape cache**; host sends shape and hotspot on change only | RDP pointer PDUs, g-r-d `PointerCached`, HP `0x450`, SudoVDA hardware cursor | Zero-latency pointer feel. The biggest perceived-latency win per line of code. |
| S10 | **Virtual display per client, sized to the client's backing pixels, with dynamic modes and stable per-client serials** | HP (SkyLight dynamic geometry), DeskPad (CGVirtualDisplay), g-r-d `RecordVirtual`, KWin zkde virtual outputs, SudoVDA | 1:1 pixels = sharp text; per-client remembered layouts. |
| S11 | **Virtual displays as leases** (watchdog unplugs them if the host dies) | SudoVDA watchdog + Apollo ping thread (`Driver.cpp:380-400,1488-1491`; `virtual_display.cpp:601-618`) | Never strand a user's windows on an invisible display. CGVirtualDisplay already behaves this way per process; enforce the same per session. |
| S12 | **One GPU pass for convert + damage + 4:4:4 split**, then HW encode from the same device | g-r-d `grd-avc-dual-view.comp` + VAAPI on the Vulkan device | Zero-copy Linux pipeline; the same idea maps to a Metal compute pass on macOS if Sunna does AVC444-style 4:4:4. |
| S13 | **System broker + per-session agent + handover**, with login-window agents | Apple DTS guidance + RustDesk `[Aqua, LoginWindow]` agent; g-r-d system/handover daemons | Always-available hosts including the login screen. ### 7.2 Avoid

| # | What | Seen in | Why |
|---|---|---|---|
| A1 | Reliable, in-order transport for graphics or input | RDP GFX (non-lossy DVC; RDPEUDP2 reliable-only), Apple HP input over TCP | Head-of-line blocking is the dominant latency spike on lossy Wi-Fi/Internet paths. |
| A2 | Recovery that is FIR/IDR-first or NACK-only | Apple HP (FIR + NACK, no FEC), Sunna today | At least one RTT per repair; big 4:4:4 IDRs cause freezes on long paths. Use FEC + deadline-aware NACK + LTR. |
| A3 | Constant-QP encode with fps throttling as the only rate control | g-r-d (CQP 22 VAAPI, VBR targetQuality 22 NVENC) | Unbounded bitrate spikes on full-screen changes; no graceful degradation on thin links. Keep a QP ceiling but drive bitrate from congestion control. |
| A4 | Encoder restart + IDR on every resize | Apple HP | Visible hitch. Scale during drag, commit on release; reconfigure without a full reset where the codec allows. |
| A5 | CGDisplayStream / legacy CG capture | Sunna today, RustDesk, DeskPad | Obsoleted in the 15 SDK, no frames from virtual displays on 15+, triggers re-prompts. |
| A6 | Unsigned or ad-hoc host binaries, or hosting from Terminal | Sunna today | TCC grants reset on every rebuild or attach to Terminal. Ship a signed agent bundle with a stable identity. |
| A7 | Capturing from a LaunchDaemon | common mistake (forums 768146) | Unsupported. Capture in per-session LaunchAgents only. |
| A8 | Relying on portals alone for unattended Linux | RustDesk (pre-Aug 2026) | Dialog on first use or every connection, backend-dependent persistence, no greeter. |
| A9 | Single codec per session, no content classification | FreeRDP shadow, xrdp | Wastes bits on text and blurs it; can't converge to lossless. |
| A10 | DWT/RemoteFX-class codecs as the primary codec | RDP 8 | Never lossless (quant ≥ 6), CPU-heavy, obsolete next to hardware H.264/HEVC. Use lossless tiles for text and HW video for motion. |
| A11 | Alternating main/aux views in one reference chain without reference management | AVC444 as naively implemented (FreeRDP) | Poor inter prediction and inflated aux frames. If Sunna does dual-view, give the aux view its own reference chain or LTR slots. |
| A12 | Windowed, compositor-mediated presentation as the only mode; `waitUntilCompleted` on the present thread | moonlight-qt vsync-off path | Adds 1-5+ compositor frames on macOS. Design for fullscreen direct-to-display and async completion. |
| A13 | Promising HP-level 4:4:4 before verifying public VT support | — | FFmpeg shows only `Main42210` exposed. Run the M1/M2 `chroma_format_idc` experiment first (§3.2). |
| A14 | Fixed well-known ports, one session per machine | Apple HP (UDP 5900-5902) | NAT/VPN fragility (sing-box #4155). Use QUIC on a negotiated port and multiplex sessions. |
| A15 | World-executable capability binaries | RustDesk DRM helper concern | Any local user could read other sessions' screens. Group-restrict and authenticate the helper IPC. |

### 7.3 Concrete additions to 07-v1-plan implied by this research [INFER]

1. **Step 3 (host capture):** migrate to SCK *before* the virtual-display step; CGDisplayStream can't capture CGVirtualDisplay on 15+. Keep `dirtyRects` and `displayTime`, and handle `.idle`.
2. **Step 3/6:** turn on `EnableLTR` and temporal layering early; it's the root fix for IDR storms. Add a VT property probe that logs unsupported keys and dumps supported `ProfileLevel` values (the HEVC 4:4:4 question).
3. **Step 4 (cursor):** use `CGSCurrentCursorSeed` + `NSCursor.currentSystemCursor` (RustDesk method) with a shape cache keyed by hash.
4. **Step 8 (lossless tiles):** extend to RDP-style scroll blits (S3) and a content-addressed client cache (S1). Apply video through region masks (S2).
5. **Step 9 (4:4:4):** decision tree = public VT HEVC 4:4:4 if the probe succeeds → else AVC444v2-style aux view via a Metal compute split (S12) with separate reference handling (A11) → lossless tiles cover static text either way.
6. **Step 11 (ship shape):** signed `Sunna.app` + root daemon broker + `[Aqua, LoginWindow]` agent `.app` (min macOS 14.4 for login-window SCK); apply for `persistent-content-capture` now; Core Audio taps for audio; lazy clipboard.
7. **Linux host (post-v1):** start with Mutter/KWin private virtual monitors + libei (what g-r-d and krdp prove works), a portal fallback with persisted restore tokens, and an opt-in KMS+uinput helper for greeter/unattended use. On the owner's GPU-less VM: virtio-gpu linear framebuffer + x264 zerolatency + the lossless tile path.
8. **Benchmark (step 1):** adopt the HP procedure in notes 05 §5 (photodiode rig, AWDL control, LAN/Tailscale-direct/DERP matrix, `presentedTime`).
