2026-10-11. Reviewed the brief, both reports, local source, Microsoft/vendor documentation, issue bodies/comments, and the VDD release artifact. No Sunna files were edited; no commands or experiments were run on Valkyris. **The OV-only plan is plausible for carefully built x64 UMDF packages, but its all-protections-on deployment claim remains UNVERIFIED. ## Important omissions

- **Virtual audio changes the signing plan.** Headless render endpoints and general microphone passthrough need an actual endpoint solution; WASAPI loopback does not create one. The [SysVAD project](https://github.com/microsoft/Windows-driver-samples/blob/main/audio/sysvad/TabletAudioSample/TabletAudioSample.vcxproj) builds a kernel driver linked with `portcls.lib`. [Microsoft's ACX overview](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/acx-audio-class-extensions-overview) explicitly says both legacy PortCls and newer ACX are kernel mode; ACX uses KMDF, not UMDF. Thus **the supported SysVAD/PortCls/ACX route cannot reuse ordinary OV-only UMDF signing**. Plan Microsoft kernel signing plus HVCI validation, or a redistributable already-signed audio component with suitable terms. Attestation's technical desktop trust and its documented testing-purpose restriction must both be considered; HLK is the production certification route. [VirtualDrivers audio issue #15](https://github.com/VirtualDrivers/Virtual-Audio-Driver/issues/15) independently shows audio signing failures despite the project's working display-signing route. No documented general UMDF-only replacement was established.
- **Define the decisive deployment experiment.** On a separate clean test machine, record Windows build and *running/enforced* Secure Boot, HVCI and SAC states; use the intended IV/OV signer and exact production package; record UAC/SmartScreen/PnP prompts, `setupapi.dev.log`, CodeIntegrity events, loaded driver DLL/PE flags, device functionality, reboot and update behaviour. Explicitly compare CAT-only with CAT + embedded DLL signing. A successful `pnputil` staging result is insufficient. This experiment was **not performed**, and Valkyris must remain read-only.
- **Uninstall ownership and SYSTEM boundaries.** Remove only Sunna-owned device instances/packages/certificates, not every ghost Xbox/HID node or a publisher certificate shared with another product. An MSI does not automatically make external PnP/custom actions transactional. Keep network parsing, update verification and driver IOCTL authorization under explicit privilege/rollback design. “SYSTEM fixes UIPI” is not a complete security architecture.

## Contradictions between the reports

- **Audio versus “EV can be deferred forever”:** Astra §6/§9 requires signed virtual audio for full headless/mic support. Fable §0/§3/§9 budgets only UMDF display/gamepad drivers and treats kernel signing as optional. The audio row above resolves this dependency in favour of an explicit kernel-driver/redistribution plan.
- **NVIDIA phantom output:** Fable §2 calls Valkyris's 1024×768 WMI entry an active, capturable NVIDIA output and extrapolates no-driver behaviour. Astra §8 records `Display Attached: No`, `Display Active: Disabled`, and explicitly says WMI mode data do not enumerate active paths. **The evidence does not support Fable's conclusion.** A read-only CCD/DXGI active-output inventory would be needed; Parsec being installed also defeats the stock-machine inference.
- **WGC certainty:** Fable §5 says WGC cannot capture secure desktop “at all”; Astra §2.5 labels general coverage unverified. Retain the latter qualification and use documented privileged DDA as the baseline.
- **Release scope:** Fable §9 ships v1 requiring a physical display/dummy plug; Astra's complete-headless design requires installed virtual display/audio. This is a scope decision, not an API disagreement: that Fable v1 is not yet a self-contained headless host.
- **Internal Fable contradiction:** §1.2 treats ViGEm loading on Valkyris as evidence for Secure Boot/HVCI compatibility, while §8 explicitly records both protections **off**. Those observations cannot validate the all-protections-on claim.
