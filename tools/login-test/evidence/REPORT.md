## Research/17 Part 1 review and verification

The Linux system host now closes the connection when the active graphical session changes. The desktop viewer keeps its window, reconnects, and negotiates the replacement worker’s screen size. The host sends an ordinary QUIC application close with code zero and the reason `session changed`. Protocol 8 keeps its existing postcard field and variant positions. A deployed viewer can reconnect manually.

### Login handoff

These measurements used Ubuntu 24.04, two emulated CPUs, no guest network interface beyond loopback, H.264 at 640×400 and a 5 fps client request. The independent X client maps alternating red and cyan bars during Xsession startup and records guest uptime after `XSync`. The viewer timestamps its first decoded replacement frame and saves the first picture whose chroma matches all four bars. Password time is the client queuing Return. The seat sample and worker PID sample can lag scheduler activity. The host journal supplies the observer and worker-ready times in the optimized runs.

### Implementation decisions

The stable recovery executable is a validated copy of the signed supervisor. This reuses its journal recovery and version validation without introducing a second updater implementation. A clean worker exit after input teardown and the final X round trip serves as the acknowledgement within the 750 ms limit. Sunna refuses the entire ambiguous regular-user session because its per-user services cannot safely identify one desktop. X11 greeters can coexist because their display endpoint is verified and the host suppresses their clipboard and audio.

### Shared interfaces

- `sunna_host::SessionDevices::bind_viewer` returns the worker’s native size and a session-validity callback. `FrameSource::take_cursor` has a default implementation. The viewer associates its input sender with the frame it actually displays. The close reason is transport metadata. Authenticated probes and Hello retain their existing wire variants.
- `/run/sunna-host/listening` contains the numeric socket address. `receipt` contains `InvocationID child-PID frame|empty`. `shares-greeter` contains `1` or `0` after observation; absence means unknown. All three are staged, chmodded to 0644 and atomically renamed in a root-owned directory. The consumer verifies the invocation and live child. Private settings and credentials stay under `/etc/sunna`.
- The Linux signed launcher provides `system-serve host`, `run-user host`, `run-desktop host` and `validate-listen`. Portal callers can distinguish `has_restore_token()` from `approved()`. [Linux host guide](../../../docs/host-linux.md)

The privilege checks cover concrete cases. Unrelated local system administrators remain trusted. The system listener holds the machine credential and the network connection. ### Remaining questions

Physical hardware, multi-seat, KDE Wayland user sessions, full system-mode media across a live seat change, and end-to-end remote-login performance outside CPU emulation still need testing. The GNOME 46 portal rerun used the existing per-user host. The system-mode approved-user Wayland path and the regular-user portal on GNOME 49 and 50 were not verified end to end. The locally generated signed system installer was exercised. The public release endpoint was not changed. The worker preserves the negotiated stream size by scaling after a seat change. The system mode currently supplies no remote cursor-shape stream. A missing supervisor cannot answer probes until systemd has restarted it. The reported greeter capability reflects the last greeter the running service observed.

### Implementation and shared interfaces

- The systemd unit runs the existing signed update supervisor. Its child owns QUIC, the machine key, the viewer slot and the encoder. A seat observer gets the active local session from login1. It checks the selected session and UID through libsystemd before publishing frames or forwarding input. The viewer retains its negotiated size. During a handoff the listener returns blank frames and drops input until it has shown the new worker’s output. [Linux listener](../../../apps/sunnad/src/linux_machine.rs) · [Seat selection](../../../apps/sunnad/src/linux_seat.rs)
- A worker starts the same verified executable with its private inherited sockets, the session UID/GID and a new environment. X11 display discovery, Xauthority, portal access, sound and clipboard backends all run there. Media has its own socket so a blocked clipboard or audio device leaves input and pictures independent. The root process checks payload size, worker ownership and seat selection. The system service omits session media on greeters. [Worker](../../../apps/sunnad/src/linux_worker.rs) · [Media](../../../apps/sunnad/src/linux_media.rs)
- The public Rust host entry point `run_host` remains available to existing callers. `run_host_with_desktop` adds a watched `DesktopState` and optional `SessionDevices` for session-routed audio and clipboard. `ClipboardSession::start_with` lets the established clipboard synchronization logic use a worker backend. The installer and updater add Linux-only `install-system`, plus delayed readiness in `host::start_after` and a Linux desktop-wait marker. The supervisor never treats that marker as proof of capture or input. [Host API](../../../crates/host/src/lib.rs) · [Updater](../../../crates/update/src/host.rs)
- The wire change appends `NotSharing { detail }` as a separate optional authenticated message. The original postcard enum positions and ProbeAck fields are retained. The client exposes `not-sharing` and its detail. Local status reports `managed_by` and the observed greeter capability, and omits the system credential. [Protocol](../../../crates/proto/src/messages.rs) · [Client reach check](../../../crates/client/src/reach.rs) · [System CLI](../../../scripts/system-host.sh)

The initial LightDM Xvfb trial produced pictures but could not register a genuine VT for its greeter in logind. The matrix uses the QEMU seats. In two early VM runs a hand-staged fixture archive changed the guest filesystem root to mode 0700. This prevented system D-Bus from starting as its normal user. The root mode was restored to 0755 and the reboot and session tests were repeated. The repository fixture installs the feed directly under its own directory. The release installer made no change to the guest filesystem root. After collecting the evidence, the named fixture containers, images, disk volumes and temporary builds were removed.
