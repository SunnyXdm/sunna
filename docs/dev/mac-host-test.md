# Verify the menu bar host on a Mac

Use a test account on a Mac running macOS 13 or newer and a second Sunna viewer. Keep the test Mac on a trusted network. Record macOS version and build (`sw_vers`), processor (`uname -m`), Sunna revision, FileVault status, and whether Tailscale is connected. Repeat at least the permission and login steps on the oldest supported and current macOS. These are expected results. No Mac measurements have been collected.

## Diagnostics for every step

Record the step, local time, observed message, and expected result. For any failure, run the following on the host within ten minutes. Send the filtered job summary, relevant host stderr lines and matching unified-log lines after reviewing them for private information. Omit keys, links, QR codes, environment dumps and unrelated personal information.

```sh
job="gui/$(id -u)/dev.sunna.host"
plist="$HOME/Library/LaunchAgents/dev.sunna.host.plist"
launchctl print "$job" | awk '/^[[:space:]]*(state|pid|runs|last exit code|program) = /'
tail -n 60 "$HOME/Library/Logs/Sunna/host.stderr"
/usr/bin/log show --last 10m --style compact --predicate '(process == "launchd" AND eventMessage CONTAINS[c] "dev.sunna.host") OR (process == "tccd" AND eventMessage CONTAINS[c] "sunna") OR process == "Sunna-real"'
```

Before first enable and after removal, a missing job is expected. A missing log before first enable is expected. For a foreground host, use its Terminal stderr. In the steps below, **send diagnostics** means the evidence above plus the observation named in that step.

1. **Install.** From the checkout run `scripts/install-mac-app.sh` without `--adhoc`. If an existing window is open, close it first. Complete local certificate setup. Open Settings. On a fresh account the switch is off. Record the installed bundle path printed by the installer. Use it below for `app`. Both commands should print the same designated requirement. Save both lines for the update comparison. On failure send diagnostics and the signing error.

   ```sh
   app=/Applications/Sunna.app  # use "$HOME/Applications/Sunna.app" if installed there
   codesign --verify --strict "$app"
   codesign -d -r- "$app" 2>&1 | sed -n '/^designated =>/p'
   codesign -d -r- "$app/Contents/MacOS/Sunna-real" 2>&1 | sed -n '/^designated =>/p'
   ```

2. **Check background-item attribution before granting access.** Turn on sharing. In System Settings → General → Login Items (Login Items & Extensions on newer versions), record the name and publisher under Allow in the Background. Expect one Sunna item. Record an unidentified item, a certificate name, a second item, or a disabled background item as a failure. Compare the bundle and launcher TeamIdentifier using `codesign -dv --verbose=4` on each. Apple requires matching team identifiers and a bundle known to Launch Services. Record a missing TeamIdentifier explicitly when testing the local certificate. [Apple’s legacy helper association](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos)

    Read the separate explanations for Screen Recording and Accessibility. Check that the menu exists, shows a waiting reason and has no host Dock icon. Run `plutil -lint "$plist"`. The job summary should show one PID. Probe from the viewer using a saved link, or the host menu’s Copy Link. Expect “Waiting for permission on that Mac”. A connection must not get a picture or input. Send diagnostics, the pane labels and which permission was missing.

3. **Grant separately.** Click each permission button in Settings, granting one at a time. In Privacy & Security record the displayed app name and whether macOS asks to relaunch. After the first grant repeat the authenticated probe and try connecting. Expect the same waiting reason and no frame. After both are effective it should show sharing, its address and “Nobody is connected”. Require a ready authenticated probe from the second device, then connect and move a distinctive window on the Mac. Confirm the viewer shows that movement and accepts a keystroke. Record whether there is exactly one Sunna entry in each pane. A checkmark alone does not pass this step. On macOS 15+ record any local-network prompt separately. If a relaunch is required, first record the host and window states, then stop sharing from the menu, quit the window, reopen and enable again. Send diagnostics for any mismatch or extra TCC row.

4. **Close the window and measure idle.** Open Activity Monitor, choose All Processes, and record the host PID from the job summary. Close Sunna’s main window using the red button. Expect the menu bar host and no remaining launcher window process, Sunna update supervisor or Sunna WebKit view. Check both appearances. Wait 60 seconds with the viewer app closed so it sends no probes. Sample ten times, and record actual RSS in KiB, Activity Monitor’s Memory value, CPU percentage and idle wakeups. In Activity Monitor’s Energy view enable View → Columns → Idle Wake Ups, locate Sunna by the host PID, and record ten readings two seconds apart in wakeups per second. [Apple’s wakeup measurement procedure](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html)

   Compare samples using the same tool in steps 5 and 6. Send diagnostics, all samples and process names on failure.

   ```sh
   pid=$(launchctl print "$job" | awk '$1 == "pid" && $2 == "=" {print $3; exit}')
   for i in $(seq 1 10); do ps -p "$pid" -o pid=,rss=,%cpu=,time=,comm=; sleep 2; done
   pmset -g assertions | grep -i caffeinate
   ```

5. **Connect.** From the second device use Copy Link or the Settings QR code, then connect. Move a window, type into a throwaway document, play a system sound and check the viewer hears it. Expect a filled menu icon and the viewer name. Run `pmset -g assertions` and identify the idle-system-sleep assertion held by caffeinate for the host. Record connected memory/CPU. From the menu choose Stop Sharing, then Cancel. Repeat using the switch, cancelling again. The current session should continue. Send diagnostics, assertion details and which media or input failed.

6. **Disconnect.** Quit the viewer, wait 60 seconds and repeat step 4 with the same host PID. Expect the unfilled icon, “Nobody is connected”, no host sleep assertion, and CPU returning to idle. Record the numbers even if higher than expected. Send diagnostics and both sets of measurements if memory grows across three connect/disconnect cycles.

7. **Crash, quit and login.** Without a viewer, use Activity Monitor to Force Quit only the host PID identified in step 4. Expect a new PID and one menu item. Choose Quit Sunna Host and confirm its stated duration. Wait 30 seconds. The plist should remain, with no serving process. Reopen Settings, turn sharing off and on, and reconnect. Quit the host from the menu again. Run `scripts/install-mac-app.sh --no-open` twice, waiting for each update to finish. Record the selected version after each run and verify that sharing stays paused, the plist’s first ProgramArguments entry is executable, and its path names the newly selected bundle. Reboot, unlock FileVault if enabled, and log into this account. Before opening the window, require a ready remote probe and an actual moving frame on the viewer. There is no pre-login desktop. Send diagnostics, timestamps, old/new PIDs and any background-item notification.

8. **Update while connected.** Save the PID, designated requirements from step 1 and the value of `readlink "$HOME/.local/share/sunna/app/current"`. Make a connection and close the launcher window. Run `scripts/install-mac-app.sh --no-open` again. Its local adopted version changes even if the source version is identical. During installation exercise the viewer; the old host PID should continue until disconnect. Disconnect. Allow the installer to finish, then verify the version link changed, the host PID changed, and both requirements exactly match the saved lines. Reconnect without granting either permission again. With an approved signed release staged in Settings → Updates, also repeat with **Restart to update** during a connection. The window may exit while the supervisor waits. Send diagnostics, versions, PIDs, requirements and any repeated grant dialog.

9. **Lose permission and recover a stale grant.** With a viewer connected, turn off Screen Recording for Sunna. Record whether macOS applies it immediately or asks for a relaunch. After it takes effect, the session should end, the menu should explain why, and a new authenticated probe should report the waiting reason. Restore the grant and repeat for Accessibility. If Settings lists Sunna as on while the app says it is denied, record the two states; in the pane opened by the app, select Sunna, remove it with minus, add the installed bundle again and enable it. Follow any required relaunch, then reconnect. For a deliberate stale-signature fixture use a disposable account with an old differently signed copy and grant it before installing the local certificate build. Record whether the installer cleared the old entry automatically. Send diagnostics, pane name, app name, actual restart requirement and time to recovery. Leave an unattended test enabled for an extended period and record any later reauthorization prompt and what a remote probe sees.

10. **Network and foreground host.** Turn sharing off. Stop Tailscale on the test Mac, leave Wi-Fi or Ethernet connected and enable sharing again. Expect the LAN address in Settings and the menu; connect using a new link. Disconnect the viewer, bring Tailscale up without touching sharing, and allow up to three minutes for the menu and Settings to show the Tailscale address. Reconnect using the original Tailscale link and require a moving frame. Turn sharing off again, and run `~/.local/bin/sunna host` in Terminal using the saved key. Expect one icon, no login plist, and an on switch; turn it off from the app. Terminal should return to its prompt. If an old run.sh/sunnad installation is available, repeat the switch check against that foreground host on port 48800. Send diagnostics, network type, the displayed reach, and the number of listeners.

11. **Finish off.** Enable sharing, connect, choose Stop Sharing and confirm this time. The viewer should disconnect, the icon disappear, `test ! -e "$plist"` succeed and `launchctl print "$job"` report no such service. Close the window and verify no Sunna process remains in Activity Monitor. Log out and in again. Expect no icon or listener. Send diagnostics, any remaining PID and whether the plist or loaded job survived.

## Update and move fault checks

Use a disposable macOS account with a working, confirmed source installation and an enabled agent.

1. While disconnected, note the current version link and host PID. Revoke Accessibility and verify that the authenticated probe reports the missing grant. Close the window. Run `scripts/install-mac-app.sh --no-open` to stage a different adopted version. Candidate validation should fail, the installer should report rollback and the previous version link should be restored. The old host should answer the waiting probe. Grant access and reconnect. Send diagnostics, both version links and the failed release listed in the app updater state. Run this separately from the ordinary update test.
2. For a move test, use an independent, locally signed copy of Sunna.app in a private test directory. Always launch its actual bundle with `open -n "/path/to/Sunna.app"`, checking which window the menu opens. Enable sharing, close the window, connect, then move that bundle to a different private directory in Finder and open it there. Close its window before disconnecting. The session should continue. After disconnect, the job’s program path should change to the new bundle and a fresh session should work. Stop sharing there before removing the test copy. Send diagnostics and both paths. Moving the installed Applications symlink alone leaves the underlying versioned bundle in the same location.
3. With sharing off, have a throwaway UDP listener occupy the chosen address on port 48800. For example, run `python3 -c 'import socket, time; s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.bind(("0.0.0.0",48800)); time.sleep(120)'` in a test Terminal. Turn sharing on. Expect a port error. Stop only that test listener with Control-C, turn sharing off and on, and reconnect. Send diagnostics and the exact error sentence.

## Platform references and unresolved observations

The items below are ordered by the uncertainty that remains after source inspection and Rust cross-compilation.

1. **Unattended permission loss.** The host checks the calling process’s current screen and input grants on each authenticated connection and during an active session. Requesting Accessibility is asynchronous. On each supported OS, check when a change becomes observable, whether stopping/reopening the host or window is necessary, what a periodic reauthorization prompt does, and whether the system ever filters pixels while the preflight still returns true. Apple documents the persistent entitlement and its approval process. Sunna does not ship it. [Screen preflight](https://developer.apple.com/documentation/coregraphics/cgpreflightscreencaptureaccess%28%29) · [Screen request](https://developer.apple.com/documentation/coregraphics/cgrequestscreencaptureaccess%28%29) · [Accessibility trust](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions) · [Persistent capture](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.persistent-content-capture)
2. **Identity and delivery.** Check that a locally signed supervisor, its signed Sunna-real child, the launchd exec path and a terminal invocation get the intended TCC attribution. Compare the designated requirements across the source installer, release signer, actual bundle move and rollback. Record Gatekeeper dialogs, keychain prompts, duplicate rows, any stale allowed row and whether both pane URLs work. The pane URLs are implementation conventions for System Settings; use the manual Privacy & Security path if the OS ignores one. [Apple’s designated requirements](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements) · [macOS open(1)](https://keith.github.io/xcode-man-pages/open.1.html)
3. **Capture, sound and input.** Exercise real moving pixels, typing, a static display, permission revocation, display sleep and system sound. Check whether the legacy CGDisplayStream backend still produces usable frames on the tested macOS. A stopped stream and an initial frame timeout are treated as errors. After a successful stop, teardown holds the stream and queue until the final callback. Two failed stop calls cause the host to exit so the OS reclaims live capture resources. Record any PID change or repeated restart. ScreenCaptureKit supplies the existing audio backend. [Frame statuses](https://developer.apple.com/documentation/coregraphics/cgdisplaystreamframestatus) · [Apple’s stop and release contract](https://developer.apple.com/documentation/coregraphics/cgdisplaystreamstop?language=objc) · [System audio](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/capturesaudio)
4. **Login, updates and routing.** Confirm the GUI domain, background-item controls, launcher path resolution, clean exit, crash retry, throttling, bootout from the job’s own menu, the deferred bundle move and both update paths on APFS. At login the network may come up after the job. Record actual LAN and Tailscale reach on each network, including any local-network authorization on macOS 15+. For migration, verify that the same-user lsof record identifies the previous Terminal host. FileVault unlock and graphical login precede this user agent. [Apple launchd guide](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html) · [macOS launchctl(1)](https://keith.github.io/xcode-man-pages/launchctl.1.html) · [macOS launchd.plist(5)](https://keith.github.io/xcode-man-pages/launchd.plist.5.html) · [macOS lsof(8)](https://keith.github.io/xcode-man-pages/lsof.8.html) · [Local network privacy](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [Usage description](https://developer.apple.com/documentation/bundleresources/information-property-list/nslocalnetworkusagedescription) · [FileVault](https://support.apple.com/guide/security-pdf/managing-filevault-sec8447f5049/web)
5. **Menu and window.** Check for one status item, no host Dock icon, template appearance in both themes, a filled connected variant, correct labels while the menu is open, safe cancellation and a working private Copy Link. Verify Open Sunna with and without a running window. The main queue updates AppKit objects. Check the host’s alert and launch behavior when another app is full screen. [Accessory policy](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/accessory) · [Status items](https://developer.apple.com/documentation/appkit/nsstatusitem) · [Template images](https://developer.apple.com/documentation/appkit/nsimage/istemplate) · [Menu items](https://developer.apple.com/documentation/appkit/nsmenuitem) · [Alerts](https://developer.apple.com/documentation/appkit/nsalert) · [Pasteboard](https://developer.apple.com/documentation/appkit/nspasteboard) · [Running applications](https://developer.apple.com/documentation/appkit/nsrunningapplication) · [Main queue](https://developer.apple.com/documentation/dispatch/dispatchqueue/main) · [objc2 AppKit signatures](https://docs.rs/objc2-app-kit/0.3.2/objc2_app_kit/) · [dispatch2 signatures](https://docs.rs/dispatch2/0.3.1/dispatch2/struct.DispatchQueue.html)
6. **Idle cost and sleep.** Measure actual process count, CPU, memory, wakeups and resource reclamation using the table. Confirm there is no remaining web view, encoder, capture stream, audio capture or host sleep assertion after disconnect. The existing session guard invokes caffeinate with the idle-system assertion and watches the host PID. Check that powerd releases it on disconnect and forced exit. [Apple’s caffeinate implementation](https://github.com/apple-oss-distributions/PowerManagement/blob/main/caffeinate/caffeinate.c)

## Readiness and key persistence

In a fresh test account, open Settings before enabling sharing. Enable it, change a viewing preference in the same sheet and restart the host. Connect using the original link. Repeat after quitting and reopening Sunna. Check the connection without including keys in the test report.

With both permissions granted, obtain a ready probe, disconnect the viewer, and put the display to sleep or disconnect it. Probe after 60 seconds and record the waiting state and the result of the next frame check. Wake or reconnect the display and probe through the 10-second retry interval. Record whether an actual frame arrived in each configuration. Core Graphics distinguishes complete, idle, blank and stopped updates. [Apple frame statuses](https://developer.apple.com/documentation/coregraphics/cgdisplaystreamframestatus)
